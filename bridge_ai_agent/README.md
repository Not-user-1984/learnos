# bridge_ai_agent — задачи между Claude и исполнителем

**Claude** — архитектор и ревьювер: пишет только `.md` в этой папке, код не трогает.
**Исполнитель** — другая нейронка: пишет код по плану.

## Файлы

```
bridge_ai_agent/
  BOARD.md              доска: одна строка на задачу
  B-001-slug/plan.md    задача (пишет Claude)
  B-001-slug/report.md  отчёт (пишет исполнитель)
  B-001-slug/review.md  ревью, по раундам (пишет Claude)
```

## Статусы

`todo → doing → review → done`; если есть замечания: `review → fix → doing → review`.

- Claude ставит `todo` (создал), `fix` или `done` (после ревью).
- Исполнитель ставит `doing` (взял) и `review` (сдал).

## Исполнитель: «возьми задачу» / «возьми B-NNN»

1. В `BOARD.md` возьми B-NNN или первую `fix`, иначе первую `todo`. Поставь `doing`.
2. Прочитай `plan.md` (при `fix` — ещё последний раунд `review.md`). Делай только то, что в плане.
3. Код, тесты, команды проверок из плана.
4. Запиши `report.md` списком: изменённые файлы, результаты проверок, отклонения от плана, вопросы.
5. Поставь `review`. Коммит и пуш — только после `done`, если в плане не сказано иное.

Если что-то в плане неясно или неверно — не придумывай: запиши вопрос в `report.md` и поставь `review`.

## Claude: «проверь B-NNN»

Сделай `git diff` и запусти проверки, сверь с планом, допиши раунд в `review.md`, поставь `fix` или `done`.

## Шаблон plan.md

```
# B-NNN: заголовок
Цель: …  /  Готово, когда: … (проверяемо)
Контекст: файл:строка — что там сейчас
Изменения: путь → что сделать (словами, сигнатуры)
Тесты: …
Проверки: точные команды
Риски / вопросы: …
```

Экономим токены: читаем только `BOARD.md` и папку своей задачи; пишем списками, план не пересказываем.
