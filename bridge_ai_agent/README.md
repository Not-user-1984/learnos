# bridge_ai_agent — общая папка архитектора и исполнителя

**Claude** — архитектор и ревьювер: пишет только `.md` в этой папке, код не трогает.
**Исполнитель** — другая нейронка (OpenCode, ZCode и т.п.): пишет код по плану.

## Что где лежит

```
bridge_ai_agent/
  README.md             этот протокол
  BOARD.md              доска задач: одна строка на задачу
  INDEX.md              оглавление docs/: одна строка на документ
  docs/*.md             знания о проекте: архитектура, решения, карта кода (пишет Claude)
  B-001-slug/plan.md    задача (Claude)
  B-001-slug/report.md  отчёт (исполнитель)
  B-001-slug/review.md  ревью по раундам (Claude)
```

Сначала читай `BOARD.md` и `INDEX.md`, остальное — только по нужной задаче или теме.

## Статусы

`todo → doing → review → done`; при замечаниях: `review → fix → doing → review`.

- Claude ставит `todo` (создал), `fix` или `done` (после ревью).
- Исполнитель ставит `doing` (взял) и `review` (сдал).

## Исполнитель

Команды: «посмотри bridge, исполняй», «исполняй все задачи» — вся очередь; «возьми задачу» — одна
следующая; «возьми B-NNN» — конкретная.

**Работай полностью автономно и до конца очереди.** Не останавливайся, чтобы спросить человека:
его нет рядом.

1. В `BOARD.md` возьми указанную задачу, иначе первую `fix`, иначе первую `todo`. Поставь `doing`.
2. Прочитай `plan.md` (при `fix` — ещё последний раунд `review.md`) и нужные документы из `INDEX.md`.
   Делай то, что в плане, и не больше.
3. Код, тесты, команды проверок из плана. Добивайся зелёных проверок сам: читай ошибки, чини, повторяй.
4. Мелкая неясность — прими разумное решение в духе плана и запиши его в `report.md`.
   Настоящий блокер (план противоречит коду, нужен доступ или секрет) — опиши его в `report.md`,
   поставь `review` и переходи к следующей задаче.
5. Запиши `report.md` списком: изменённые файлы, результаты проверок, отклонения и принятые решения, вопросы.
6. Поставь `review` и бери следующую задачу. Закончились `todo`/`fix` — остановись.
7. Коммит и пуш — только после `done`, если в плане не сказано иное.

## Claude

- «Проверь» / «исполнил, перепроверь»: по каждой задаче в `review` — `git diff`, проверки, сверка с планом,
  раунд в `review.md`, статус `fix` или `done`.
- Новое знание о проекте (как устроен модуль, принятое решение) — в `docs/<тема>.md` + строка в `INDEX.md`,
  чтобы не исследовать код заново.

## Шаблон plan.md

```
# B-NNN: заголовок
Цель: …  /  Готово, когда: … (проверяемо)
Контекст: файл:строка — что там сейчас (и ссылки на docs/)
Изменения: путь → что сделать (словами, сигнатуры)
Тесты: …
Проверки: точные команды
Риски / вопросы: …
```

Экономим токены: пишем списками, план и код не пересказываем.
