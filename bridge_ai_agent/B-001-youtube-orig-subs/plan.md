# B-001 · YouTube: брать оригинальные автосубтитры, не переводы

## Цель
YouTube-источники с автосубтитрами обрабатываются. Сейчас падают с «субтитры не найдены (ru/en)».
Если причина в другом, текст ошибки виден в UI.

## Диагноз (проверен 2026-11-11, видео YqJ4asgj1R8, источник прода id=10 `src_4425608e`)
- У видео нет ручных субтитров. Оригинальная автодорожка — **`en-orig`**. Дорожки `en` и `ru` в
  automatic_captions — это **машинные переводы** (`tlang`).
- Скилл запрашивает `--sub-langs ru,en`. yt-dlp первым качает перевод `ru`, получает
  **HTTP 429** и прерывается целиком, поэтому `en` не скачан и файлов нет. Скилл отдаёт вводящую в заблуждение
  ошибку «субтитры не найдены».
- `--sub-langs en-orig` скачивается сразу (390 КБ VTT, текст корректный).
- Прокси (xray) работает, ключи и LLM ни при чём.
- В `jobs.error` пишется только `result["error"]` (`server/app/modules/library/service.py:309`), stderr
  теряется. У `sources` нет поля ошибки, в UI отображается просто `failed`.

## Файлы
- `server/skills/youtube-to-summary/run.py` — `main()` (стр. ~65–125)
- `server/app/modules/library/service.py:300-311` — запись ошибки job
- API или схема источника и web-карточка источника — для показа последней ошибки (найди сам: где отдаётся
  `GET /api/sources/{ref}` и где в web рисуется статус `failed`)
- тесты скилла и library в `server/tests/`

## Шаги
1. **run.py — языки.** `--sub-langs "ru-orig,en-orig,ru,en"` и добавить `--ignore-errors`. Тогда 429 на
   переводе не прерывает загрузку остальных дорожек: yt-dlp при ignoreerrors пишет только warning.
2. **run.py — выбор файла по приоритету.** Сортировка по алфавиту больше не нужна. Порядок: ручные `ru`, ручные `en` →
   `ru-orig` → `en-orig` → переведённые `ru` → `en`. Вынеси в чистую функцию `_pick_sub(paths) -> Path | None`.
   Отличить ручную дорожку от переводной по имени файла нельзя: оба будут `ID.ru.vtt`. Поэтому
   приоритет такой: сначала любой `*-orig`, затем `ru`, затем `en`. Это приемлемо: если `-orig` нет, значит были ручные
   субтитры, а у них имена без суффикса.
   Перед запуском удаляй старые `ID.*.vtt|srt` этого видео (после неудачных попыток могут остаться частичные файлы).
   `lang` в результате — суффикс выбранного файла (`en-orig` → `en`).
3. **run.py — честная ошибка.** Нет файлов и в stderr есть `429` → error
   `"YouTube ограничил запросы (429), повторите позже"`. Нет файлов без 429 → текущий текст. В обоих случаях
   в `error` добавить хвост stderr (до 200 символов), чтобы он попал в `jobs.error`.
4. **Показ ошибки.** В ответ источника (REST и MCP, тот же сериализатор) добавить `last_error: str | None` —
   `error` последнего job `process_source` этого источника, только при `status == "failed"`. Миграция не нужна, данные берутся из
   `jobs`. Web: на карточке или странице источника со статусом `failed` показать `last_error` мелким
   текстом (семантические токены, см. `web/DESIGN.md`). Типы — через `npm run gen:api`.
5. **Тесты.**
   - `_pick_sub`: набор `{ru, en, en-orig}` → `en-orig`; `{ru, en}` → `ru`; пусто → `None`.
   - Формирование cmd содержит `--ignore-errors` и `ru-orig,en-orig,ru,en` (замокать `subprocess.run`).
   - Ветка 429: stderr с `HTTP Error 429`, файлов нет → текст про 429.
   - `last_error` отдаётся у failed-источника и равен `None` у остальных.
6. **Прод.** Обычный воркфлоу проекта: проверки → коммит → push → автодеплой. После деплоя
   `POST /api/sources/src_4425608e/process` (с bearer-токеном через `sec exec`). Дождаться статуса, проверить,
   что источник обработан (появились главы или текст).

## Риски
- 429 бьёт по IP. Если `en-orig` тоже получит 429, ошибка станет честной (шаг 3), но обработка не пройдёт. Тогда в
  отчёте указать это и не делать ретраи в цикле.
- `--ignore-errors` может замаскировать реальный провал. Его ловит проверка «нет файлов» в шаге 2/3.
- Whisper-fallback в задачу **не входит**.
