## Зачем

Harness-архитектура, заточенная на обучение: один корневой разговор, который сам
понимает контент (PDF → книга, YouTube → видео, тема → ресёрч, «повтори» →
review) и вызывает агентов как субагентов; агенты создают и правят свои
скрипты/скиллы; агент ревизует систему. Вместо режимов и шести точек входа —
один умный вход с новым дизайном.

## Зафиксированные решения (пользователь, 2026-10-28)

1. **Агентские скиллы** живут в `data/agent-skills/<agent>/<skill>/` — вне git,
   рантайм-область. `server/skills/` — только builtin-скиллы продукта.
2. **Старых режимов в UI не сохраняем** — сразу переход на корневого агента
   вместе с новым дизайном чата (бэкенд-режимы/`agent:<name>` остаются для
   MCP-совместимости старых разговоров).
3. **Новый дизайн чата** (T-039): стартовый экран в духе Claude — приветствие +
   крупный инпут; история разговоров внизу, при начале ввода анимационно
   схлопывается и начинается диалог; сценарные кнопки («Закрепить пройденное»,
   «Конспект», «Собрать курс» и др.) остаются. Дизайн — по токенам
   `web/DESIGN.md`, новые экраны — через скилл hallmark.
4. **Вся работа эпика — в ветке `t-034-orchestrator`**, не в main. Пуш ветки —
   свободно (деплой смотрит только main). Мердж в main = релиз, только после
   ревью ZCode (главного агента).
5. **Конвейер**: learnos-dev делает подзадачу по ub-mode → ставит на ревью ZCode
   (код, тесты, линты; для UI — визуальная проверка) → мердж в main → деплой.
   Отдельный QA-агент не заводим (меньше сущностей); QA — ZCode по чек-листу
   ниже.
6. **Саморевизия — ступени** (решение по этапу D): строим ступень 1 (read-only
   auditor + задачи) и ступень 2 (агент готовит ветку/коммит + карточка «применить»,
   мердж за человеком). Ступень 3 (авто-пуш в main) — отдельным решением позже;
   предусловие — авто-rollback по health-метке в deploy-скрипте CT 132 (репо
   proxmox). Запрет-лист навсегда: `bootstrap.py`, `main.py`, `alembic/`,
   LLM-слой/`llm.yaml`, deploy-скрипты, docker-compose, guard-модуль.

## Аудит кодовой базы (2026-10-28, основа плана)

Готово к переиспользованию: `AgentRuntime` (`server/app/agent/runtime.py`) с
устойчивостью к падению инструментов; `AgentRegistry`; `ToolRegistry` с
per-agent наборами (`AgentSpec.tools`); `AgentContext.parent_run_id` уже течёт
через рантайм; карточки `propose_prompt_change`/`note_draft`; research-режим как
прецедент «поведение без режима».

Пробелы: нет инструмента вызова агента (субагентов нет вообще); `ToolRegistry.call`
синхронный в async-цикле — нужен офлоад; `parent_run_id` не пишется в БД
(`agent/recorder.py:32`, колонки нет); события субагента не показываются в
родительском SSE; скиллы не видны агентам (`torrent_fetch` обещан
`RESEARCH_DIRECTIVE`, но отсутствует в `free_chat.tools` — `chat/service.py:49`
vs `chat/agents.py:17-41`); `MessageIn` без вложений, автодетекта контента нет;
exec/файлов нет; UI: 6 мест создают разговор с зашитым режимом и клиентской
директивой (`new-conversation.tsx`, `study-flow.tsx`, `source-actions.tsx`,
`reader.tsx`, `block-page-client.tsx`, `agents-settings.tsx`); `repo_scout`
недоступен из чата.
