## Что было нужно

Любой материал, созданный пользователем, удаляется из UI с диалогом подтверждения. Сейчас удаление есть только у части сущностей, а API-эндпоинты и UI не согласованы.

Инвентарь на 2026-10-22 (проверено по коду):

| Сущность | API DELETE | UI удаление |
|---|---|---|
| Источник (library) | ✓ `DELETE /api/sources/{ref}` | ✓ список библиотеки, с диалогом; при живых блоках сервер запрещает |
| Курс | ✓ `DELETE /api/courses/{ref}` (элементы каскадом) | ✗ |
| Разговор | ✓ `DELETE /api/conversations/{uid}` | ✗ |
| Кастомный агент | ✓ `DELETE /api/tuning/agents/{name}` | ✓ настройки |
| Внешний MCP | ✓ `DELETE /api/mcpext/{name}` | ✓ настройки |
| Блок БЗ | ✗ | ✗ |
| Категория БЗ | ✗ | ✗ |
| Активность | ✗ | ✗ |
| Сессия | ✗ | ✗ |

## Сделано (9f13d5a)

**API:**
- `DELETE /api/kb/blocks/{uid}` — блок + `block_versions` + md-файл в `kb/blocks/` + поисковая
  строка (событие `BlockDeleted` → search убирает из `blocks_fts`);
- `DELETE /api/activities/{ref}` — разговоры отвязываются (история чата остаётся), активность удаляется;
- `DELETE /api/sessions/{ref}` — разговор остаётся, панель сессии в нём исчезает.

**Политика зависимостей** — как с источниками, без каскадов в v1, ошибки 409 с русским сообщением:
- блок не удаляется, если входит в элементы курса (`courses.count_items_for_block`, связка
  `knowledge.bind_courses` в bootstrap);
- активность не удаляется, если у неё есть сессии;
- сессия не удаляется, если по ней создан блок БЗ (`knowledge.count_for_session`);
- источник — уже запрещён при живых блоках, не трогали.

**UI:** единый `ConfirmDeleteButton` (`web/src/components/confirm-delete.tsx`) — сам делает DELETE,
тостит успех/ошибку сервера (409 показывается из ответа), после — router.refresh() или редирект.
Подключён:
- курс: карточка в списке `/courses` (иконка на hover) + страница курса (редирект в список);
- разговор: карточка в списке `/chat` + шапка чата (редирект в список);
- блок БЗ: страница блока, колонка «Действия» (редирект в `/kb`);
- активность: страница источника — плашка «Изучение идёт: глава N из M» с кнопкой «Прекратить»;
- библиотека переведена с локального диалога на общий компонент.

**Решения по неоднозначностям** (в духе задачи):
- сессии в UI отдельно не удаляются: сессия нигде не показывается сама по себе (только панель
  в чате), API — есть, UI подключим, если появится экран сессий;
- активность в UI = только активная (`status=active`) по источнику; завершённые не показываем;
- категории БЗ не в скопе (как и договаривались — отдельно, только пустые);
- удаление сессии/активности НЕ ломает ядро «блок рождается через сессию»: блок хранит
  session_uid как источник, поэтому сессия с блоком и не удаляется.
