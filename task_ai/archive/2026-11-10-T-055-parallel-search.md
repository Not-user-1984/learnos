## Что нужно

Первый непустой результат поиска приходит за время самого быстрого живого звена,
а не суммы всех звеньев (BB-002: на продах без ключей Tavily/Serper web_search
занимал десятки секунд — цепочка и академ-агрегат строго последовательные).

- `ChainProvider.search`: параллельный fan-out всех звеньев (ThreadPoolExecutor,
  провайдеры синхронные), «первый непустой побеждает», остальные игнорируются;
  падение/пустота звена не роняет цепочку, ошибки собираются в error-строку как
  сейчас; двойной проход при пустоте убрать (без повторных сетевых ходов).
- Таймауты звеньев: ddg 8с, wikipedia 6с, hackernews 6с, tavily/serper 10с.
- `_academic_agg` (ResearchService): arXiv + OpenAlex + Semantic Scholar параллельно;
  дедуп, `_interleave`, сводка counts/failed — семантика ответа не меняется.
- Кеш 20 мин + single-flight (`_cached`) — не трогать.
- Смоук на проду: research-поиск заметно быстрее (без ключей цепочка = ddg+wiki+hn параллельно).

Ограничение: только `server/app/modules/research/` и его тесты (параллельно другая
группа режет llm-слой и web-настройки — пересечений по файлам нет). Веб не трогать.

## Критерии готовности

- [x] ChainProvider: первый непустый побеждает, медленное звено не блокирует результат
- [x] Пустая цепочка — ровно один проход по звеньям, ошибки в error-строке
- [x] Таймауты звеньев снижены (ddg 8 / wiki 6 / hn 6 / tavily 10 / serper 10)
- [x] Академ-агрегат параллелен; дедуп/interleave/counts/failed не сломаны
- [x] Тесты: fan-out, отсутствие второго прохода, таймауты, параллельность академа (+4, всего 436)
- [x] `ruff`/`format`/`lint-imports`/`pytest` зелёные
- [x] Прод проверен: web_search 1.1–1.3 с (chain/ddg, 5 результатов), academic 0.7–1.1 с

## Заметки

- Потоки в fan-out недемонические: при раннем возврате (первый непустой) пул
  гасится `shutdown(wait=False, cancel_futures=True)` — недоработавшие запросы
  дозавершаются в фоне с коротким таймаутом (≤10с), на процесс не влияют.
- Семантика ответа `chain/<name>` у победившего звена и `chain` при пустоте —
  сохранена (тесты `test_chain_*` прошли без правок).
- `_academic_agg` ждёт все три источника (pool.map) — по ТЗ агрегат собирает
  всё; латентность = max звеньев, а не сумма.
- **Инцидент инфраструктуры во время деплоя (починен на месте):** деплой CT 132
  падал с 2026-11-08 — tailscaled на Proxmox-хосте переписал хостовый
  /etc/resolv.conf на MagicDNS (100.100.100.100), недостижимый из CT → git fetch
  не резолвил github.com. Чинка: `tailscale set --accept-dns=false` на хосте,
  resolv.conf хоста и CT = nameserver 192.168.0.1 + fallback 77.88.8.8.
  Затем сборка падала на `disk quota exceeded` (30G диск, 35GB docker-образов,
  190 dangling от старых деплоев) → `docker image prune -f` освободил 32GB.
  После чистки build + CI-гейт + up прошли, health зелёный.
