## Контекст (диагноз уже проведён, факты проверены)

Пользователь читает Pro Git (src_caeb226b, 533 стр.): «главы не соответствуют», quick-разбор зациклен на «первой главе», PDF-навигация непонятная, режим чтения без картинок. Ресерч кода и файла выявил корневые причины:

1. **Мусорные закладки → главы.** `server/skills/book-splitter/run.py:59-61` берёт закладки уровня 1 без фильтрации: у Pro Git 7 из 21 «глав» — мусор (титул, оглавление, лицензия, посвящения, вступление, указатель). Реальная глава 1 книги = idx 8 в БД/UI → «глава 3» в UI = лицензия.
2. **Quick-разбор прибит к курсору.** Контекст каждого хода пишет «Текущая глава {cursor}» (`app/modules/chat/service.py:352`), курсор двигает только `finish_session` (`app/modules/learning/service.py:306-315`); у quick-агента такого тула нет → вечная «глава 1» (= титульная страница после п.1).
3. **Outline-эндпоинт матчит по названиям** (`app/modules/library/service.py:407-453`): нормализация + `setdefault`, промах → «предыдущая+1» или страница 1. Хрупко; у Pro Git работает, но из-за п.1 нумерация врёт. Страницы глав в БД не хранятся.
4. **Картинки теряются.** Сплиттер — `page.get_text("blocks")`, image-блоки выбрасываются. Проверено: `page.get_text("dict")` отдаёт text/image-блоки interleaved в правильном порядке (в Pro Git 192 картинки, у главы «Ветвление» блок IMAGE стоит ровно между текстом и подписью «Рисунок N»).
5. **Подразделы level-2 выбрасываются** → главы-монстры («Инструменты Git» = 126 стр.).
6. **Баги доставки книг (найдены при заливке тестовых книг):**
   - хук на media-CT `/opt/media/scripts/learnos-qbit-hook.sh`: ищет крупнейший PDF во всём `$DIR` (общий /downloads у всех раздач) → льёт не ту книгу; `curl -F "file=@${PDF}"` падает (exit 26) на запятой в имени файла — нужен `file=@"${PDF}"`; ошибки curl не логируются.
   - `app/modules/skills/loader.py:128-131`: optional-параметр скилла без `default` получает аннотацию `str` и дефолт `None` → MCP-клиент передаёт null → pydantic «Input should be a valid string» (ломает вызов torrent_fetch напрямую).

Тестовые книги на проде (все `status=processed`, старым сплиттером): id 5 Pro Git (21 гл.), id 7 Рамальо (12), id 9 Любанович (6 из ~20!), id 10 Лутц т.1 (12), id 11 Свейгарт (10).

## Что нужно

### Э1. Куратор структуры книги (LLM-агент)
- Новый агент `structure_curator` по образцу `chapter_summarizer` (`app/modules/library/service.py:292-341`, промпты `app/agents/<name>/prompt.md` — проверить фактический путь). Вход: полный TOC pymupdf (все уровни, ~122 записи) + первые строки текста ключевых кандидатов. Выход JSON: для каждой записи level-1 — класс `chapter` (номер главы книги) / `front_matter` (мусор) / `appendix` (приложение — тоже глава, номер «A/B/C» или без числа). LLM НЕ определяет границы страниц — только классифицирует записи; границы остаются от закладок.
- Фолбэк без LLM — эвристика: стоп-слова (оглавление/contents/licence/лицензия/dedication/посвящение/index/указатель/титул/cover), длина < 3 страниц, позиция до первого содержательного блока.
- front_matter не создаёт глав; его текст (кратко) уходит в `sources.summary`/описание (склейка с тем, что делает source_overviewer).
- Секции level-2: сохранить в `chapters.sections_json` = `[{"title", "page"}]` (только для глав).

### Э2. Хранение страниц и навигация
- Миграция Alembic 0008: `chapters` + `number` (int | null — номер главы книги), `start_page` (int), `end_page` (int | null), `sections_json` (Text, default "[]").
- book-splitter пишет эти поля (start_page из TOC, end_page = след. закладка).
- `/api/sources/{ref}/outline` (`chapter_pages`): страницы из БД (fallback на текущий матч по названию — для старых источников). В ответ добавить `sections` и `numbers`.
- Удаление старых images/ при переобработке (см. Э3).

### Э3. Картинки в режиме чтения
- Сплиттер: `page.get_text("dict")` вместо `"blocks"`; для image-блока — рендер bbox (`page.get_pixmap(clip=bbox, dpi≈150-200)`) → PNG в `data/sources/<id>/images/img_p{page}_{n}.png`; в .md главы на позиции блока вставлять `![рисунок](/api/sources/{uid}/images/img_p{page}_{n}.png)`. Подписи «Рисунок N» остаются текстом рядом. Пропускать декоративные мелкие картинки (высота < ~40pt).
- Новый эндпоинт `GET /api/sources/{ref}/images/{name}` — FileResponse, только из каталога images этого источника (защита от path traversal).
- Проверить, что web-Markdown рендерит `img` (react-markdown дефолт) и картинки тянутся через прокси `/api/...`.
