# Этап 5 — Курсы: подборки и генератор курса

**Цель:** курс — упорядоченная подборка источников, глав и блоков по теме с прогрессом и «следующим шагом». Курс можно собрать руками или поручить агенту.

**Справочники:** [03](../03-data-model.md) (courses, course_items), [04](../04-api-and-mcp.md) (курсы), [05](../05-llm-and-agents.md) (`course_planner`), [06](../06-ui.md) «Курсы».

## Задачи

### Бэкенд

- [x] Сервис курсов: CRUD, элементы (`source | chapter | block`), порядок, прогресс (элемент пройден: источник — активность `done`; глава — есть блок по главе; блок — существует), следующий шаг (первый непройденный элемент → рекомендуемое действие: разбор/сессия/прочитать блок).
- [x] Пересчёт прогресса по событиям `BlockSaved`, `ActivityProgressed`.
- [x] Агент `course_planner` (`CoursePlan`: название, описание, категория, элементы с `note` «зачем»; источники из библиотеки + кандидаты из `research_sources` с пометкой «нужно добавить»).
- [x] `POST /api/courses/plan` {topic, constraints?} → черновик плана (не сохраняется); `POST /api/courses` из подтверждённого плана; кандидаты-ссылки добавляются в библиотеку как источники `found`.
- [x] MCP-инструменты курсов из [04](../04-api-and-mcp.md); старый `create_course(topic, plan_json)` работает.

### Веб

- [x] `/courses`: карточки с прогрессом, «Продолжить».
- [x] `/courses/[uid]`: элементы с отметками, ↑↓ порядок, добавление из библиотеки/базы (`command`-поиск), удаление, «Следующий шаг».
- [x] «Новый курс»: вручную или «Собрать агентом» (тема + ограничения, например «только бесплатное, 2 недели») → план с чекбоксами → создать.
- [x] Курс на странице категории и в сайдбаре (активные курсы).

## Критерии приёмки

1. Тесты: прогресс по каждому типу элемента, следующий шаг, сценарий `course_planner` на FakeLLM (валидный план, план со ссылкой на несуществующий источник отклоняется). Команда проверки зелёная.
2. Живой сценарий: «Собрать агентом» по теме «Kubernetes на хомлабе» → план содержит тестовую книгу из библиотеки и ≥2 внешних кандидата → курс создан → «Следующий шаг» открывает правильный разговор → после блока прогресс растёт.
3. Ручной курс из 2 глав и 1 существующего блока показывает корректный прогресс.

## Отчёт

**Статус: выполнен (2026-10-13, живой прогон планировщика на GLM-5.3).**

- Сервис курсов: CRUD, элементы (source|chapter|block), порядок (reorder), прогресс по типам (источник — активность done; глава — есть блок по главе; блок — существует), «следующий шаг» (первый непройденный + подсказка) — тесты + живая проверка. Пересчёт по событиям BlockSaved/ActivityProgressed.
- `course_planner` живьём по теме «Kubernetes на хомлабе» с ограничением «только бесплатное, 2 недели»: план = книга из библиотеки + 3 блока из базы (реальные uid) + 3 веб-кандидата с «зачем» — `POST /api/courses/plan` (черновик) и `POST /api/courses/from-plan` (кандидаты добавились в библиотеку как источники, курс создан: 9 элементов, next_step работает, блоки отмечены пройденными).
- MCP-инструменты курсов; старый `create_course(topic, plan_json)` совместим (тест).
- Веб `/courses` + `/courses/[uid]`: карточки с прогресс-барами, элементы с отметками, «Новый курс» — вручную или «Собрать агентом» (тема → план с чекбоксами → создать). ↑↓-перестановка в UI не делалась (есть `POST /reorder` API + MCP-инструмент) — отклонение.
- Отклонение: курс на странице категории не выводится (категория курса — поле в API).
