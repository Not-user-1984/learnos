## Что нужно

Архитектурные улучшения harness из аудита (разделы A, B, F) + P1-дефекты:

- **A. Handoff вместо «root + одноразовые субагенты»** (закрывает R-13, часть R-04/R-12):
  `conversations.active_agent` вместо mode; интент первого сообщения выставляет активного
  специалиста (review→quick_reviewer, session→session_tutor, tune→prompt_tuner,
  reinforce→reviewer); инструмент `handoff(agent, reason)` / `handoff_back()`; директивы
  интента перестают быть одноразовой вставкой — педагогика живёт в промптах специалистов;
  бейдж «сейчас ведёт: …» в UI; root худеет (~60 схем инструментов в каждом запросе).
- **B. Слой управления контекстом**: явный `ToolResult` (data/card/window/truncation/
  summary_for_history); бюджет по токенам (кириллица ≈ 2.2–2.5 симв./токен, не 3.5);
  компактация истории через fast-агента `conversation_summarizer` → `conversations.summary`;
  tool-результаты в истории как компактные резюме (R-12: сейчас теряются полностью, карточки
  тоже невидимы в следующих ходах); ленивая загрузка схем инструментов (tool_search);
  prompt caching стабильным префиксом.
- **F. Eval-харнесс**: 15–30 золотых сценариев `tests/evals/*.yaml` на живой модели;
  линтер «промпт ↔ инструменты» уже сделан в T-048 — расширить на все агенты/скиллы.
- **R-11** `start_activity` не идемпотентен → дубли активностей, размазанный прогресс;
  get-or-create по (source_id, course_id, status=active) + миграция слияния дублей.
- **R-14** Jinja в промптах падает на `{{ … }}` (DevOps-контент) → подстановка по явному
  списку (string.Template/str.replace) + пробный рендер при stage_change/create_custom_agent.
- **R-15** Override-промпты замещают базу целиком (правки базы не доезжают) → base_sha +
  «база изменилась» + 3-way merge; apply без сверки old_content; reject после apply;
  два источника data_dir (Settings вместо env); LLM отдаёт полный промпт → patch-операции.
- **R-24** Наблюдаемость: structured-вызовы пишут tokens=0, steps=1; нет трассы шагов →
  таблица `agent_steps(run_id, idx, kind, name, args_json, result_summary, ok, ms, tokens)`,
  usage из structured_output, экран трасс в вебе, счётчик стоимости по ролям/дням.
- **R-29** Инструменты внешних MCP не доступны встроенным агентам (extend_tools только для
  скиллов) → дать root mcp_* или переформулировать UI; учесть prompt injection из внешних MCP.
- Права инструментов (E, частично): классы read/write_kb/exec/external_effect/admin;
  exec/admin только по подтверждению; «агент с web_read не получает save_skill» — решить
  судьбу save_skill у root (lethal trifecta, см. T-049 заметки); `save_skill` новых скриптов
  через карточку с подтверждением.

4. **Э4 handoff (A)**: conversations.active_agent, интент → специалист, handoff()/handoff_back(),

5. **Э5 слой контекста (B, включая R-12)**: резюме tool-результатов в истории, компактация
   conversation.summary, токен-бюджет под кириллицу, ленивые схемы инструментов
