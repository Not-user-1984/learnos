# 01 — Продукт: видение, словарь, принципы

## Видение

LearnOS — личная система обучения одного человека (Дмитрий, DevOps/разработчик). Аналог Google NotebookLM, но:

- **персональный** — знает моё железо, мои прошлые блоки, мой стиль («объясни через аналогию»);
- **активный** — не только отвечает по источнику, а ведёт урок: объясняет, спрашивает, даёт практику;
- **копит знания** — всё пройденное оседает в базе знаний в сжатом виде, по категориям, в Markdown;
- **открытый** — тот же функционал через MCP из любого агента (opencode в терминале и т.д.).

Темы любые: программирование (Python → ООП), инфраструктура (Kubernetes на хомлабе), личное (рецепт омлета).

## Словарь (используй эти слова в коде, UI и промптах)

| Термин | Что это |
|---|---|
| **Источник** (source) | Загруженный материал: книга PDF, YouTube-видео, веб-статья. Разбит на **главы** (у видео — одна или несколько частей транскрипта). Живёт в **Библиотеке** независимо от курсов. |
| **Глава** (chapter) | Часть источника: текст в файле + краткое summary + ключевые пункты (генерирует LLM при обработке). |
| **Активность** (activity) | «Идём по этому источнику»: прохождение книги/видео по главам с курсором прогресса. «Активность книги», «активность видео». |
| **Разговор** (conversation) | Ветка чата. Режим: `free` (свободный), `quick` (быстрый разбор), `session` (сессия). |
| **Быстрый разбор** (quick) | Режим: агент резюмирует главу/источник, выделяет главное, обсуждаем. Итог — блок-**конспект** (`kind: note`). |
| **Сессия** (session) | Режим-урок 20–30 мин по стейт-машине: теория → фейнман-вопросы → практика → разбор. Итог — блок-**урок** (`kind: lesson`). |
| **Блок** (block) | Единица базы знаний: MD-файл с frontmatter. Сжатая выжимка разговора: понятия, тезисы, «как я понял», схема, практика, «дозакрепить», связи, источники. |
| **Категория** (category) | Узел дерева: `programming/python/oop`, `life/cooking`. У блока одна категория + свободные **теги**. |
| **Входящие** (inbox) | Блоки, у которых категория предложена агентом, но ещё не подтверждена мной. |
| **Курс** (course) | Подборка по теме: источники (целиком или главы) + блоки, в порядке, с прогрессом. «3 книги + 5 видео по Kubernetes». |
| **Профиль** (profile) | Мои машины (MacBook, хомлаб Proxmox, …) и предпочтения обучения. Агент использует его для практики. |
| **Карточка команды** (command card) | Шаг практики в чате: машина, команда, объяснение каждой части, ожидаемый результат, уровень риска. Выполняю я сам. |

## Принципы

1. **Знание входит в базу только через диалог с агентом.** Блок создаётся только из разговора (быстрый разбор / сессия / свободный чат по моей просьбе). Нет кнопки «импортировать файл как блок». Загруженная книга — это источник в Библиотеке, а не знание.
2. **Сессия — честная.** `finish_session` возможен только из состояния `debrief`; фейнман-этап обязателен (агент задаёт вопросы и оценивает мои ответы своими словами).
3. **Контекст LLM не захламляем.** Книги читаются по главам и порциям (`read_chapter` с offset/limit), сначала summary глав, потом нужный текст.
4. **Markdown — формат знаний.** Блоки и дерево категорий — файлы в `kb/` (git, Obsidian, экспорт). БД — индекс и операционное состояние.
5. **Одно ядро — три лица.** MCP, веб-чат и REST вызывают одни и те же функции ядра через один реестр инструментов.
6. **Практику выполняю я.** Агент предлагает команды под моё железо и объясняет каждую; он ничего не запускает на моих машинах (песочницы — в бэклоге).
7. **Блоки живые.** Агент может улучшать блок в любом разговоре («добавь в омлет, что соль в конце») — правка применяется сразу, старая версия сохраняется, откат в один клик.

## Решения пользователя (2026-10-13)

| Вопрос | Решение |
|---|---|
| Режимы | Два: «Быстрый разбор» (→ конспект `note`) и «Сессия» (→ урок `lesson`) |
| Правка блоков через чат | Агент правит сразу, без подтверждения; история версий + откат |
| Ручной редактор MD в вебе | Не нужен в v1 |
| Практика | Агент даёт команды с объяснением, выполняю сам, вывод вставляю в чат. Песочницы Proxmox — позже |
| Категории | Дерево + свободные теги. Агент предлагает категорию, я подтверждаю (Входящие) |
| Сборщик | opencode |
| Приоритет | Чат и агент → база знаний → библиотека → курсы → экспорт → бэклог |
| LLM | Не привязываемся к одной модели: слой провайдеров + роли моделей в конфиге. Старт — z.ai GLM (`glm-5.3`), автоматического fallback между провайдерами нет |
| Бэкенд | Модульный монолит, слоистая архитектура, русские docstring, тесты на всех уровнях — с прицелом на прод |
| Агенты | Декларативные агенты + общий рантайм с заделом под мультиагентность |
| Платформа v1 | Мак (локально). Хомлаб/мобилка — бэклог |

## Чего НЕ делаем в v1

Мультипользовательность, авторизация в вебе (сервис локальный), выполнение команд агентом, мобильное приложение, оплата, автоматическое переключение между LLM-провайдерами.
