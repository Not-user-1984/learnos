# task_ai — ТЗ на развитие LearnOS (для агента-сборщика)

Ты — агент-сборщик (opencode). Здесь описано целевое состояние LearnOS и этапы, по которым ты его собираешь. Пользователь — Дмитрий, общение и документация на русском.

## Что строим — в одном абзаце

Персональный «NotebookLM под меня»: веб-сервис + MCP. Загружаю книгу (PDF) или YouTube-видео → агент на GLM быстро разбирает источник по главам → мы с агентом проходим его в чате: **быстрый разбор** (резюме + обсуждение) или полноценная **сессия** 20–30 мин (теория → фейнман-вопросы → практика под моё железо → разбор). После каждого разговора в **базе знаний** автоматически появляется сжатый **блок** (понятия, тезисы, схема mermaid, практика, что дозакрепить), разложенный по дереву категорий. Из блоков и источников собираются **курсы**. Всё выгружается в Markdown. Тот же функционал доступен через MCP из любого клиента (opencode и пр.).

## Приоритеты (важнее порядка файлов)

ТЗ намеренно с запасом: это копилка идей, которые вводятся постепенно. Не всё обязано быть сделано, и точно не сразу.

1. **Ядро — этапы 1–3:** чат, сессия, блок, база знаний. Всё остальное имеет смысл, только если ядро хорошее.
2. **Точка «Пожить»** — после этапа 3 остановись. Пользователь неделю-две учится через систему (одна книга, одно видео, 5–7 сессий). Твоя задача в этот момент — помочь собрать впечатления: что раздражает в тьюторе, какие блоки получились водянистыми, чего не хватило. По итогам правим промпты и ТЗ, и только потом дальше. Удачные и неудачные сессии сохраняем как эталоны (`server/tests/agent/golden/`): каждая правка промптов прогоняется по ним вручную или через `cli eval-golden`.
3. **Дальше по ценности:** часть C этапа 8 (повторение в Telegram — она нужна, чтобы база не стала кладбищем, и опирается только на блоки) → этапы 4 → 5 → 6 → остальной этап 8 (A → F, затем B, E, D) → 9 → 10 → 11.
4. **«По требованию»** — не начинать, пока пользователь явно не попросит: сервис рендера визуалов (этап 9), облако и Docker (этап 10, часть F), свой Telegram-бот (этап 10, часть C), агент-пакет и курьер (этап 11). В файлах этапов они помечены.

## Как работать с этапом

1. Прочитай файл этапа целиком и нужные справочники.
2. Изучи затрагиваемый код (`server/app/*`, `web/src/*`) — файлы ТЗ описывают цель, а не текущие строки.
3. Делай задачи по порядку, отмечая `[x]` в файле этапа.
4. Этап закрыт, когда **каждый** пункт «Критерии приёмки» проверен командой или руками и результат записан в раздел «Отчёт» в конце файла этапа (что проверено, чем, что не получилось). **Общий критерий любого этапа:** контракт-тест паритета MCP зелёный, а все инструменты этого этапа из каталога [08-mcp-parity.md](08-mcp-parity.md) зарегистрированы и вызваны хотя бы раз из opencode.
5. Обнови раздел «Текущий статус» в корневом `AGENTS.md` и сообщи пользователю итог. Следующий этап — только после его «ок».

## Правила (обязательные)

- **Корневой `AGENTS.md`** — читай перед работой; его правила в силе (секреты, язык, коммиты).
- **Источник истины для цели — `task_ai/`.** Если `PLAN.md` / `ARCHITECTURE.md` расходятся с `task_ai/`, прав `task_ai/`. На этапе 1 синхронизируй `ARCHITECTURE.md` (см. задачу этапа).
- **Секреты:** ключ GLM только через `sec exec ZAI_API_KEY -- <команда>`. Значения ключей не печатать, не писать в файлы и логи.
- **Коммиты:** только когда пользователь попросит. В конце этапа предложи сообщение коммита.
- **Документация библиотек:** перед использованием Next.js 16, Tailwind v4, shadcn/ui, mermaid, MCP SDK и т.п. сверяйся с актуальной документацией (context7 MCP или официальные сайты) — версии свежие, API меняется.
- **Не ломай работающее:** текущий MCP-цикл (opencode → `start_session` → `advance` → `finish_session`) должен работать на каждом этапе. Совместимость контрактов описана в [04-api-and-mcp.md](04-api-and-mcp.md).
- **Данные пользователя:** перед миграцией БД — бэкап `data/learnos.db`. Файлы в `kb/` и `data/` не удалять.
- **Если ТЗ неоднозначно** — выбери самое простое решение, совместимое с [01-product.md](01-product.md), и запиши выбор в «Отчёт» этапа. Если выбор меняет поведение продукта — спроси пользователя.
