# Этап 11 — Агент-пакет LearnOS и «курьер», который ставит его в любые агенты

**Статус: по требованию** — не начинать, пока пользователь явно не попросит.

**Когда делать:** после этапа 10 (нужны MCP-токены и уровни доступа). Добавлено 2026-10-13 как надстройка. Если пользователь попросит раньше — можно сразу после этапа 2: тогда установка идёт без токена (только локально или через Tailscale), а части про токены доделываются после этапа 10.

## Идея

1. **Агент-пакет LearnOS** — готовый, хорошо прописанный агент для любой внешней системы (Hermes, opencode, Claude Code, Cursor, Codex, OpenClaw…): системная инструкция + набор скиллов + описание MCP-подключения + смоук-тесты. Закинул пакет — внешний агент умеет полноценно работать с LearnOS: вести сессии, разбирать источники, управлять категориями и курсами — всё через MCP (паритет — [08-mcp-parity.md](../08-mcp-parity.md)).
2. **Курьер** (`agent-courier`) — переездной агент-установщик: основной агент пользователя (opencode на маке) по команде «прокинь LearnOS в Hermes» сам изучает целевую систему (как в ней сейчас подключаются MCP, скиллы и агенты — по её документации и конфигам), ставит туда пакет, выдаёт ограниченный токен, проверяет и регистрирует установку. Курьер общий — им можно перевозить в разные системы любой пакет этого формата, LearnOS — первый.

## Формат агент-пакета v1

```
learnos-agent-pack/
├── pack.yaml          # манифест
├── AGENT.md           # системная инструкция внешнего агента
├── skills/            # скиллы в открытом формате Agent Skills (SKILL.md)
│   ├── learnos-session/SKILL.md
│   ├── learnos-quick-review/SKILL.md
│   ├── learnos-library/SKILL.md
│   ├── learnos-kb/SKILL.md          # категории, Входящие, теги, версии, понятия
│   ├── learnos-courses/SKILL.md
│   ├── learnos-review/SKILL.md
│   └── learnos-admin/SKILL.md       # настройки, модели, Telegram, токены (только уровень admin)
└── smoke.yaml         # проверки после установки
```

`pack.yaml`:

```yaml
name: learnos
version: 0.11.0+<hash>          # версия сервера + хеш содержимого пакета
description: Персональная система обучения: сессии, база знаний, курсы через MCP
mcp:
  - name: learnos
    transport: streamable-http
    url: ${LEARNOS_PUBLIC_URL}/mcp          # или /mcp/<module> для узких установок
    auth: {type: bearer, env: LEARNOS_MCP_TOKEN}
    token_request: {level: write, modules: all}   # что курьер запрашивает при установке
    prompts: true
    resources: true
agent:
  instructions: AGENT.md
  name: learnos-tutor
skills: [learnos-session, learnos-quick-review, learnos-library, learnos-kb, learnos-courses, learnos-review]
optional_skills: [learnos-admin]           # ставится только если явно попросили и токен admin
requires: {mcp_http: true, skills_standard: true}
```

`smoke.yaml` — вызовы для проверки установки: `get_health` → `ok`; `list_categories` → не ошибка; `get_profile` → есть `machines`; для `write`-токена — создать и удалить временную категорию `tmp/courier-check`.

Скиллы — строго по спецификации agentskills.io: `name` (= имя папки, `[a-z0-9-]`), `description` ≤ 1024 символа с триггерами на русском и английском, тело < 5000 токенов; специфичные поля систем — только в `metadata`.

### Содержание AGENT.md (суть)

- Кто ты: тьютор и библиотекарь LearnOS для Дмитрия; язык — русский.
- Главное правило продукта: знание попадает в базу только через `finish_session` / `save_note`; книги читаются по главам (`get_source` → `read_chapter` порциями).
- Сценарии и какой скилл/инструменты для них: добавить и разобрать источник; быстрый разбор; сессия; управление базой (категории, Входящие, теги, правки и откаты, понятия, визуалы); курсы; повторение; экспорт.
- Если система поддерживает MCP-промпты — для сессии и разбора бери `learnos_session` / `learnos_quick_review` (тот же агент, что в вебе); иначе — шаги из скиллов.
- Перед удалением, откатом, изменением настроек — подтверждение пользователя.
- В ответах давай ссылки на веб-интерфейс (`LEARNOS_PUBLIC_URL/kb/<uid>` и т.д.).

### Единый источник истины

Пакет **генерируется** сервером из того же, что использует встроенный агент: `prompt.md` агентов модулей, каталог инструментов реестра, описания режимов. Шаблоны — `server/app/agent_pack/templates/` (Jinja2), сборка — `uv run python -m app.cli build-agent-pack` → `dist/agent-pack/` (не в git) и ZIP. Ручных копий промптов нет.

## Часть B — скилл `agent-courier`

Живёт как общий скилл пользователя (канон — репозиторий `radmipa-skills`, раздаётся `skill-manager` в opencode/Cursor/Claude). Исходник пишется здесь: `agent-pack/courier/` (SKILL.md + `references/`), затем импортируется: `python3 ~/my_dev/radmipa-skills/sync.py import --source <путь к agent-pack/courier> --name agent-courier` → `sync.py export --to opencode` (по правилам skill-manager, коммит в radmipa-skills — с разрешения пользователя).

Шаги курьера (тело SKILL.md):

1. **Что и куда.** Источник пакета (URL LearnOS или путь к ZIP), целевая система, где она живёт: локально / по SSH (`host`) / в контейнере хомлаба (через `pve.py exec`). Не ясно — спросить.
2. **Разведка системы.** Определить, установлена ли система и какая версия. **Прочитать её актуальную документацию** (context7 / официальный сайт) и текущие конфиги: где подключаются MCP-серверы, где лежат скиллы, как задаётся системная инструкция/агент, где хранятся секреты. Справочники `references/<система>.md` — стартовая точка; если документация расходится со справочником, верить документации и обновить справочник.
3. **Пакет.** Скачать манифест и ZIP, проверить совместимость (`requires`).
4. **Доступ.** Через MCP LearnOS (`create_mcp_token`) выпустить токен с запрошенными в `token_request` уровнем и модулями, с именем `<система>@<host>`. Значение токена кладётся **только** в механизм секретов целевой системы (например, `.env`), в конфиге — ссылка на переменную. Токен не печатается в чат и лог.
5. **Установка** по справочнику системы: MCP-подключение, скиллы, системная инструкция/агент. Перед изменением чужих конфигов — бэкап файла рядом (`.bak-<дата>`). Ничего не удалять из существующей конфигурации.
6. **Проверка.** Перезапустить/перечитать конфиг системы, убедиться, что она видит инструменты LearnOS; прогнать `smoke.yaml` (через саму систему, если у неё есть неинтерактивный запуск, иначе — тем же токеном напрямую).
7. **Регистрация.** `register_agent_install` (система, хост, версия пакета, id токена).
8. **Отчёт пользователю:** куда что встало, как запустить агента в этой системе, как обновить и как отозвать.

Режимы курьера: `install`, `update` (сравнить версию пакета, обновить файлы, токен не трогать), `uninstall` (убрать файлы и подключение, восстановить из бэкапа то, что меняли, `revoke_agent_install`), `status` (`list_agent_installs`).

Справочники `references/` (стартовые данные, сверять с документацией при каждом запуске):

| Система | Что известно на 2026-10 |
|---|---|
| **Hermes Agent** (Nous Research) | MCP: `~/.hermes/config.yaml` → `mcp_servers.<имя>` с `url`, `headers` (`Authorization: Bearer ${env:LEARNOS_MCP_TOKEN}`), опции `prompts`, `resources`, `tools.include/exclude`, `trust` (`full` / `untrusted` — запись требует подтверждения); секреты — `~/.hermes/.env`; скиллы — `~/.hermes/skills/<имя>/SKILL.md` или `skills.external_dirs`; личность агента — `~/.hermes/SOUL.md` (содержимое AGENT.md добавлять отдельным блоком, не затирая); проверить в документации раздел «Portable Agent Plugins» (`plugin.json`) — если формат подходит, ставить пакетом через него |
| **opencode** | MCP — `opencode.json` (`mcp.<имя>`: `type: remote`, `url`, `headers`); скиллы — `.opencode/skills/` проекта или глобально через skill-manager; агент — `.opencode/agent/<имя>.md`; ⚠️ не писать `skills` в проектный `opencode.json` (затирает глобальный список — правило skill-manager) |
| **Claude Code** | `claude mcp add --transport http learnos <url> --header "Authorization: Bearer …"`; скиллы — `~/.claude/skills/`; субагент — `.claude/agents/<имя>.md` |
| **Cursor** | MCP — `~/.cursor/mcp.json` или `.cursor/mcp.json`; скиллы — `.cursor/skills/` / `.agents/skills/` |
| **Codex** | скиллы — `.agents/skills/`; MCP и плагины — по документации Codex |
| **OpenClaw** (хомлаб, host-docker:18000) | изучить по месту (документация + конфиг контейнера) |

## Критерии приёмки

1. Тесты: генерация пакета детерминирована; все упомянутые инструменты существуют; скиллы проходят валидатор спецификации; `register/revoke_agent_install` отзывает токен (запрос с ним → 401).
2. Курьер из opencode на маке: «прокинь LearnOS в Hermes» (Hermes локально или в контейнере хомлаба) → токен создан, конфиг Hermes дополнен (бэкап есть), скиллы на месте, смоук зелёный, установка видна в Настройках → «Агенты и интеграции».
3. В Hermes без подсказок: «создай категорию Инфраструктура/Сети, положи туда блок про поды и начни быстрый разбор главы 3 книги про Kubernetes» → действия выполнены через MCP LearnOS, результат виден в вебе.
4. Тот же курьер ставит пакет в Claude Code или Cursor (вторая система) — смоук зелёный.
5. `update` после изменения промпта сессии на сервере обновляет пакет в Hermes; `uninstall` возвращает конфиг Hermes к исходному и отзывает токен.

Значение токена кладётся **только** в механизм секретов целевой системы (например, `.env`), в конфиге — ссылка на переменную. Токен не печатается в чат и лог.
5. **Установка** по справочнику системы: MCP-подключение, скиллы, системная инструкция/агент. Перед изменением чужих конфигов — бэкап файла рядом (`.bak-<дата>`). Ничего не удалять из существующей конфигурации.
6. **Проверка.** Перезапустить/перечитать конфиг системы, убедиться, что она видит инструменты LearnOS; прогнать `smoke.yaml` (через саму систему, если у неё есть неинтерактивный запуск, иначе — тем же токеном напрямую).
7. **Регистрация.** `register_agent_install` (система, хост, версия пакета, id токена).
8. **Отчёт пользователю:** куда что встало, как запустить агента в этой системе, как обновить и как отозвать.

Режимы курьера: `install`, `update` (сравнить версию пакета, обновить файлы, токен не трогать), `uninstall` (убрать файлы и подключение, восстановить из бэкапа то, что меняли, `revoke_agent_install`), `status` (`list_agent_installs`).

Справочники `references/` (стартовые данные, сверять с документацией при каждом запуске):

## Критерии приёмки

1. Тесты: генерация пакета детерминирована; все упомянутые инструменты существуют; скиллы проходят валидатор спецификации; `register/revoke_agent_install` отзывает токен (запрос с ним → 401).
2. Курьер из opencode на маке: «прокинь LearnOS в Hermes» (Hermes локально или в контейнере хомлаба) → токен создан, конфиг Hermes дополнен (бэкап есть), скиллы на месте, смоук зелёный, установка видна в Настройках → «Агенты и интеграции».
