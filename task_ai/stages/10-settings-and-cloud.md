# Этап 10 — Настройки, секреты, автономные скиллы, готовность к облаку

**Когда делать:** после этапа 9. Добавлено 2026-10-13 как **надстройка** (этапы 1–9 не переделываются).

**Зачем:** пользователь планирует развернуть LearnOS на облачном сервере. Значит:

1. Всё настраивается из веб-интерфейса — ключи нейронок, токен Telegram, прокси, доступы — без `sec`, Keychain и правки файлов на сервере.
2. Сервис **самодостаточен**: никаких обращений к `~/.config/opencode`, `~/my_dev/...`, Keychain, mihomo на `127.0.0.1:7890`, LaunchAgent-демонам мака. Всё нужное — внутри репозитория.
3. Сервис защищён: вход в веб, токены для MCP, секреты зашифрованы.

**Справочники:** [02](../02-architecture.md) (kernel, config, модули), [05](../05-llm-and-agents.md) (LLM-слой, роли), [06](../06-ui.md) «Настройки», [07](../07-code-standards.md), [этап 8](08-upgrades.md) C (Telegram, порт `Messenger`), исходники внешних инструментов — [reference/skills-src/](../reference/skills-src/).

Части A–F делаются по порядку, у каждой свои критерии приёмки.

**Упрощение (2026-10-13):** обязательны A, B, D, E — они полезны и на маке (ключи и модели из UI, скиллы без привязки к домашней папке). Части **C (свой бот)** и **F (prod-режим, Docker, облако)** — «по требованию»: делать, когда пользователь соберётся переезжать на сервер. До этого Telegram работает через мост-демон мака (этап 8 C).

---

## A. Хранилище секретов

- Порт `SecretStore` (`kernel/secrets.py`): `get(name)`, `set(name, value)`, `delete(name)`, `list_meta()`.
- Реализация `EncryptedSecretStore`: таблица `secrets(name PRIMARY KEY, ciphertext, last4, updated_at)`, шифрование Fernet (`cryptography`), мастер-ключ — **единственный** обязательный секрет окружения `LEARNOS_MASTER_KEY` (локально — `sec exec LEARNOS_MASTER_KEY -- …`; в облаке — env контейнера). Без мастер-ключа сохранение секретов в UI отключено с понятным объяснением, сервис работает на env-переменных.
- Приоритет: переменная окружения > хранилище (для деплоя через env и для обратной совместимости с `ZAI_API_KEY`).
- API **никогда** не возвращает значения: только `{name, is_set, last4, source: env|store, updated_at}`. Поле в UI — только запись («Заменить», «Удалить», «Проверить»).
- Фильтр логов, маскирующий значения всех известных секретов; секреты не попадают в `agent_runs`, транскрипты, ошибки, экспорт.
- `cli rotate-master-key` — перешифровать хранилище новым ключом.
- Все модули получают секреты только через `SecretStore` (никаких `os.environ` вне `kernel/config.py` и `SecretStore`).

**Критерии:** тесты шифрования/приоритета env/маскировки логов/ротации; значение секрета не находится grep'ом по БД (в открытом виде), логам и ответам API после сценария «задать ключ → вызвать LLM → получить ошибку провайдера».

## B. Нейронки: провайдеры и роли из UI

- `server/config/llm.yaml` становится **начальным значением** (seed). Рабочая конфигурация — в БД: `llm_providers(name, type, base_url, secret_name, enabled, capabilities_json)` и `llm_roles(role, provider, model, params_json)`. `ModelRouter` перечитывает конфиг по событию `LLMConfigChanged`, без рестарта.
- Пресеты провайдеров в UI (все через `openai_compat`): z.ai GLM, OpenAI, OpenRouter, DeepSeek, Groq, Ollama, LM Studio, «Свой OpenAI-совместимый» (base URL + ключ). Тип `anthropic` — когда появится адаптер (бэклог).
- Роли: `chat`, `structured`, `fast`, `vision`, **`stt`** (распознавание речи: OpenAI-совместимый `/audio/transcriptions` — Whisper у OpenAI/Groq или локальный), `embed` (на будущее). Роль может быть не настроена — зависящие функции показывают «настрой роль X в Настройках».
- «Проверить провайдера»: ключ валиден, список моделей (`GET /models`, если поддерживается) для выпадающего списка. «Проверить роль»: короткий запрос к выбранной модели (для `stt` — встроенный 3-секундный аудиофайл).
- Веб, раздел **«Модели»**: карточки провайдеров (статус, ключ ••••last4), таблица ролей с выбором провайдера/модели и кнопкой проверки.

**Критерии:** тесты роутера с перечитыванием конфига; в UI добавлен второй провайдер (например OpenRouter), роль `fast` переключена на него — summary глав идут через него без рестарта (видно в `agent_runs`).

## C. Telegram: свой бот для облака

**Статус: по требованию.**

На маке сейчас работает мост-демон (порт `Messenger`, адаптер `TelegramBridgeMessenger` из этапа 8). В облаке его нет, поэтому:

- Адаптер **`TelegramBotMessenger`**: прямой Bot API (`httpx`): отправка текста (HTML), фото/документов (PNG визуалов, MD-экспорт), получение обновлений.
  - Режим получения: **long polling** фоновой задачей (по умолчанию) или **webhook**, если задан публичный HTTPS-URL. Один поллер на бота.
  - Поддержка прокси из раздела «Сеть».
- Настройки → **«Telegram»**: режим `off | bridge (мак) | bot`; токен бота (секрет); привязка чата: UI показывает одноразовый код → пользователь пишет боту `/start <код>` → `chat_id` сохраняется (вручную chat_id не вводится); «Отправить тест».
- Предупреждение в UI: тот же бот, что у мост-демона на маке, нельзя одновременно использовать в режиме `bot` (второй поллер → ошибка 409). Рекомендация — отдельный бот для LearnOS (подсказка, как создать через @BotFather).
- Входящие в режиме `bot`: ответы на вопросы повторения (этап 8 C); ссылка YouTube/статьи → источник в Библиотеку (как «Поделиться» из этапа 8 D); PDF-файл → источник + обработка; команды `/review` (вопрос сейчас), `/stop` (пауза повторений на сегодня), `/help`. Сообщения из чужих чатов игнорируются.
- Реализацию HTTP-части Bot API (отправка файлов, прокси, обработка лимитов) можно подсмотреть в [reference/skills-src/telegram_bridge.py](../reference/skills-src/telegram_bridge.py) — переписать под порт `Messenger` и правила кода, не копировать целиком.

**Критерии:** тесты адаптера на мокнутом Bot API (`respx`): отправка, привязка по коду, игнор чужих чатов, обработка 409/429; живой сценарий на тестовом боте: привязка → тест → вопрос повторения → ответ → оценка; ссылка YouTube, отправленная боту, появилась в Библиотеке.

## D. Остальные настройки (страница `/settings`)

Структура страницы — вертикальное меню разделов слева (на мобилке — список → экран раздела), у каждого раздела кнопка «Сохранить» и индикатор несохранённых изменений. Бэкенд: `SettingsService` с типизированными pydantic-секциями в таблице `settings`, событие `SettingsChanged(section)`.

| Раздел | Что внутри |
|---|---|
| **Профиль** | имя, о себе, машины (уже есть с этапа 1) |
| **Обучение** | длительность сессии, понятия, вопросы, практика, стиль (уже есть) |
| **Повторение** | вкл/выкл, время, число вопросов, канал (Telegram/веб) — из этапа 8 C |
| **Визуалы** | стиль по умолчанию `clean/handDrawn` — из этапа 9 |
| **Модели** | часть B |
| **Telegram** | часть C |
| **Сеть** | исходящий прокси: `нет / http / socks5 / auto (мак: 127.0.0.1:7890, если слушает)`, URL прокси (секрет, если с паролем); для YouTube отдельно: прокси и **cookies-файл** (секрет-файл) — с облачных IP YouTube часто требует подтверждения «не бот» |
| **Доступ** | пароль входа в веб; MCP-токены: создать (показывается один раз), список с последним использованием, отозвать; область токена — все инструменты или модули (`/mcp/<module>`) |
| **Скиллы** | список скиллов: описание, вкл/выкл, статус требований (секреты, роли, настройки — см. часть E) |
| **Сервисы** | публичный URL, часовой пояс, URL рендер-сервиса, статусы из `/api/health` |
| **Данные** | пути (только чтение), размер `data/` и `kb/`, бэкап `kb/` в git-remote (URL + токен-секрет, расписание, «Сделать сейчас»), экспорт всего, переиндексация |

**Критерии:** каждый раздел сохраняется, переживает рестарт и применяется без рестарта (кроме смены пароля — разлогинивает остальные сессии); пустые обязательные поля подсвечены; страница проверена на ширине 390px.

## E. Скиллы внутри проекта

Цель — все нужные LearnOS инструменты живут в `server/skills/` и не зависят от мака.

### Контракт скилла v2 (обратно совместим)

- `SKILL.md` frontmatter получает опциональное поле `requires`:

```yaml
requires:
  secrets: [YOUTUBE_COOKIES]     # имена из SecretStore (опционально)
  roles: [stt]                   # роли моделей
  settings: [network.proxy]      # секции настроек
  binaries: [ffmpeg, yt-dlp]     # нужные бинарники в образе
```

- `run.py`: `main(ctx: SkillContext, **kwargs)`, где `SkillContext` даёт `settings`, `secrets`, `llm` (роутер ролей), `http` (клиент с прокси из настроек), `data_dir`, `logger`. Старый вид `main(**kwargs)` продолжает работать (загрузчик определяет по сигнатуре).
- Загрузчик проверяет `requires` и помечает скилл `ready | needs_config` (видно в Настройках → Скиллы и в `list_skills`); вызов неготового скилла → понятная ошибка «настрой …».

### Что перенести и как

| Скилл | Сейчас | Сделать | Исходник для справки |
|---|---|---|---|
| `youtube-to-summary` | есть, прокси зашит `127.0.0.1:7890`, без Whisper | прокси и cookies из настроек; **fallback на распознавание речи** через роль `stt` (аудио `yt-dlp` → `ffmpeg` чанками по 10 мин → транскрипция), вместо зашитого OpenAI | `youtube_to_text.py`, `youtube-to-summary.SKILL.md` |
| `web-search` | есть (упрощённый) | полная цепочка движков с fallback и диагностикой качества выдачи, сеть — через `ctx.http` | `web_research.py`, `web-search.SKILL.md` |
| `image-to-text` | нет | новый: OCR и описание изображений через роль `vision` (без зашитых провайдеров); используется для фото страниц из Telegram и для сканов | `image_to_text.py`, `image-to-text.SKILL.md` |
| `book-splitter` | есть | OCR-fallback: страницы без текстового слоя (скан) → рендер страницы PyMuPDF → `image-to-text`; лимит страниц на OCR в настройках | — |
| мост Telegram | внешний демон | не скилл: заменён адаптером `TelegramBotMessenger` (часть C) | `telegram_bridge.py` |

Правила переноса: исходники в [reference/skills-src/](../reference/skills-src/) — **справка**, а не код для копирования: переписать под контракт v2 и [07-code-standards.md](../07-code-standards.md), с тестами (сеть замокана). Корпоративные и личные инструменты мака (em-*, mac-fleet, firefox-pilot, browser-pilot и т.п.) в LearnOS не переносятся.

**Критерии:** `grep -rE "\.config/opencode|my_dev|127\.0\.0\.1:7890|Keychain|launchctl" server/` — пусто (кроме опции `auto` прокси в настройках сети); каждый скилл имеет тесты; YouTube-видео без субтитров транскрибируется через роль `stt`; скан-PDF (2–3 страницы картинками) разбивается на главы с текстом через OCR.

## F. Готовность к облаку

**Статус: по требованию.**

- **Режимы:** `LEARNOS_ENV=dev|prod`. В `prod` сервис не стартует без `LEARNOS_MASTER_KEY` и пароля администратора (`LEARNOS_ADMIN_PASSWORD` — только для первого старта, дальше меняется в UI); вход в веб обязателен; MCP и REST — только с токеном или сессией; cookie `Secure`, `HttpOnly`, `SameSite=Lax`; rate limit на вход.
- **Один origin:** браузер ходит только в Next (`/api/*` и `/mcp*` проксируются на бэкенд), бэкенд и рендер-сервис наружу не публикуются.
- **Docker:** образы `server` (Python + `ffmpeg` + `yt-dlp` + PyMuPDF), `web` (Next standalone), `renderer` (базовый образ Playwright); `docker-compose.yml` с томами `data/`, `kb/`, healthcheck'ами, переменными только `LEARNOS_ENV`, `LEARNOS_MASTER_KEY`, `LEARNOS_ADMIN_PASSWORD`, `LEARNOS_PUBLIC_URL`. Всё остальное — из UI.
- **HTTPS** — внешним reverse proxy; приложить пример `Caddyfile` (автоматический сертификат) в `deploy/`.
- **Бэкап:** `kb/` — в git-remote из раздела «Данные»; `data/learnos.db` — ежедневный снапшот (`sqlite3 .backup`) в `data/backups/` с ротацией 7 штук.
- **Документация:** `deploy/README.md` — запуск локально в Docker и на сервере, первый вход, перенос данных с мака (скопировать `data/` и `kb/`, задать тот же мастер-ключ или заново ввести секреты).
- Выбор хостинга и сам переезд — отдельная задача, не в этом этапе.

**Критерии:** `docker compose up` на маке поднимает все три сервиса; в `prod`-режиме без пароля/мастер-ключа сервис не стартует, без входа API отвечает 401, MCP без токена — 401, с токеном области `knowledge` виден только `/mcp/knowledge`; полный сценарий «загрузить PDF → быстрый разбор → блок» проходит внутри Docker без доступа к домашней папке мака.

  - Режим получения: **long polling** фоновой задачей (по умолчанию) или **webhook**, если задан публичный HTTPS-URL. Один поллер на бота.
  - Поддержка прокси из раздела «Сеть».
- Настройки → **«Telegram»**: режим `off | bridge (мак) | bot`; токен бота (секрет); привязка чата: UI показывает одноразовый код → пользователь пишет боту `/start <код>` → `chat_id` сохраняется (вручную chat_id не вводится); «Отправить тест».
- Предупреждение в UI: тот же бот, что у мост-демона на маке, нельзя одновременно использовать в режиме `bot` (второй поллер → ошибка 409). Рекомендация — отдельный бот для LearnOS (подсказка, как создать через @BotFather).
- Входящие в режиме `bot`: ответы на вопросы повторения (этап 8 C); ссылка YouTube/статьи → источник в Библиотеку (как «Поделиться» из этапа 8 D); PDF-файл → источник + обработка; команды `/review` (вопрос сейчас), `/stop` (пауза повторений на сегодня), `/help`. Сообщения из чужих чатов игнорируются.
- Реализацию HTTP-части Bot API (отправка файлов, прокси, обработка лимитов) можно подсмотреть в [reference/skills-src/telegram_bridge.py](../reference/skills-src/telegram_bridge.py) — переписать под порт `Messenger` и правила кода, не копировать целиком.

**Критерии:** тесты адаптера на мокнутом Bot API (`respx`): отправка, привязка по коду, игнор чужих чатов, обработка 409/429; живой сценарий на тестовом боте: привязка → тест → вопрос повторения → ответ → оценка; ссылка YouTube, отправленная боту, появилась в Библиотеке.

## E. Скиллы внутри проекта

Цель — все нужные LearnOS инструменты живут в `server/skills/` и не зависят от мака.

### Контракт скилла v2 (обратно совместим)

- `SKILL.md` frontmatter получает опциональное поле `requires`:

```yaml
requires:
  secrets: [YOUTUBE_COOKIES]     # имена из SecretStore (опционально)
  roles: [stt]                   # роли моделей
  settings: [network.proxy]      # секции настроек
  binaries: [ffmpeg, yt-dlp]     # нужные бинарники в образе
```

- `run.py`: `main(ctx: SkillContext, **kwargs)`, где `SkillContext` даёт `settings`, `secrets`, `llm` (роутер ролей), `http` (клиент с прокси из настроек), `data_dir`, `logger`. Старый вид `main(**kwargs)` продолжает работать (загрузчик определяет по сигнатуре).
- Загрузчик проверяет `requires` и помечает скилл `ready | needs_config` (видно в Настройках → Скиллы и в `list_skills`); вызов неготового скилла → понятная ошибка «настрой …».

## F. Готовность к облаку

**Статус: по требованию.**

- **Режимы:** `LEARNOS_ENV=dev|prod`. В `prod` сервис не стартует без `LEARNOS_MASTER_KEY` и пароля администратора (`LEARNOS_ADMIN_PASSWORD` — только для первого старта, дальше меняется в UI); вход в веб обязателен; MCP и REST — только с токеном или сессией; cookie `Secure`, `HttpOnly`, `SameSite=Lax`; rate limit на вход.
- **Один origin:** браузер ходит только в Next (`/api/*` и `/mcp*` проксируются на бэкенд), бэкенд и рендер-сервис наружу не публикуются.
- **Docker:** образы `server` (Python + `ffmpeg` + `yt-dlp` + PyMuPDF), `web` (Next standalone), `renderer` (базовый образ Playwright); `docker-compose.yml` с томами `data/`, `kb/`, healthcheck'ами, переменными только `LEARNOS_ENV`, `LEARNOS_MASTER_KEY`, `LEARNOS_ADMIN_PASSWORD`, `LEARNOS_PUBLIC_URL`. Всё остальное — из UI.
- **HTTPS** — внешним reverse proxy; приложить пример `Caddyfile` (автоматический сертификат) в `deploy/`.
- **Бэкап:** `kb/` — в git-remote из раздела «Данные»; `data/learnos.db` — ежедневный снапшот (`sqlite3 .backup`) в `data/backups/` с ротацией 7 штук.
- **Документация:** `deploy/README.md` — запуск локально в Docker и на сервере, первый вход, перенос данных с мака (скопировать `data/` и `kb/`, задать тот же мастер-ключ или заново ввести секреты).
- Выбор хостинга и сам переезд — отдельная задача, не в этом этапе.

**Критерии:** `docker compose up` на маке поднимает все три сервиса; в `prod`-режиме без пароля/мастер-ключа сервис не стартует, без входа API отвечает 401, MCP без токена — 401, с токеном области `knowledge` виден только `/mcp/knowledge`; полный сценарий «загрузить PDF → быстрый разбор → блок» проходит внутри Docker без доступа к домашней папке мака.
