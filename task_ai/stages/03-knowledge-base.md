# Этап 3 — База знаний: категории, теги, фильтры, страница блока, версии

**Цель:** база знаний удобна как библиотека конспектов: дерево категорий, Входящие, фильтры и сортировки, красивая страница блока со всеми секциями, история версий.

**Справочники:** [03](../03-data-model.md) (blocks, categories.yaml, формат MD), [04](../04-api-and-mcp.md) (REST `/api/kb/*`), [06](../06-ui.md) «База знаний», «Блок».

## Задачи

### Бэкенд

- [x] `GET /api/kb/blocks` со всеми фильтрами/сортировками/пагинацией из [04](../04-api-and-mcp.md); `GET /api/kb/tags`; `GET /api/kb/inbox`.
- [x] Категории: дерево со счётчиками (включая подкатегории), `POST/PATCH /api/kb/categories` (пишут `kb/categories.yaml` + индекс), `create_category` и `set_block_category` для агента; подтверждение категории из UI (`category_status=confirmed`, правка frontmatter).
- [x] Версии: `GET …/versions`, `GET …/versions/{v}`, `POST …/restore/{v}` (откат тоже создаёт версию).
- [x] `GET /api/kb/blocks/{uid}` возвращает карту `links` uid → title/summary для рендера связей и обратные связи (кто ссылается на блок).
- [x] Страница категории: `GET /api/kb/categories/{path}` — подкатегории, блоки, источники с блоками в категории.

### Веб

- [x] `/kb`: дерево категорий (цвет/иконка), Входящие с принятием/сменой категории, панель фильтров (nuqs), сортировка, сетка/список, пагинация или бесконечная прокрутка, пустые состояния.
- [x] Карточка блока по [06](../06-ui.md).
- [x] `/kb/[uid]`: шапка, раскрывающиеся секции с иконками, сетка понятий, полноэкранная схема, связи-чипы с hover-card, обратные связи, правая колонка (оглавление, метаданные, действия: обсудить в чате, повторить сессией, скопировать/скачать MD, история версий с просмотром и откатом).
- [x] `/kb/c/[...path]` — страница категории.
- [x] Настройки → «Категории»: редактор дерева (название, цвет, иконка, порядок).
- [x] ⌘K: поиск блоков по FTS с подсветкой совпадений, переход к категории.

## Критерии приёмки

1. Тесты: фильтры и сортировки (каждый параметр), счётчики дерева, подтверждение категории меняет frontmatter, откат версии, правка `categories.yaml` → индекс. Команда проверки зелёная.
2. С 10+ тестовыми блоками в 3 категориях (фабрика данных, команда `cli seed-demo` — не в прод-данные, а в отдельный `LEARNOS_DATA_DIR`/`LEARNOS_KB_DIR`) каждый фильтр и сортировка в UI даёт ожидаемый набор; URL с фильтрами открывается в новой вкладке с тем же результатом.
3. Блок из «Входящих» после «Принять» исчезает из Входящих, лежит в своей категории, в MD-файле `category_status: confirmed`.
4. Страница блока показывает все секции формата v2, mermaid в полноэкранном режиме, связи с заголовками; «Обсудить в чате» открывает разговор с блоком в контексте (агент отвечает с опорой на блок).
5. История версий: правка через чат → видна версия → просмотр → откат → контент совпадает с исходным.
6. Lighthouse (мобильный) для `/kb` и `/kb/[uid]`: Accessibility ≥ 90. Проверено в тёмной и светлой теме на ширине 390px.

## Отчёт

**Статус: выполнен (2026-10-13).**

- Все фильтры/сортировки/пагинация `/api/kb/blocks` (+`/api/kb/tags`, `/api/kb/inbox`); категории: дерево со счётчиками (включая подкатегории), `POST/PATCH /api/kb/categories` (YAML + индекс), `create_category`/`set_block_category` для агента; подтверждение из UI меняет frontmatter (`category_status: confirmed` — проверено живьём: после подтверждения блок исчез из Входящих).
- Версии: список/просмотр/откат (откат создаёт новую версию) — покрыто тестами и сервисными вызовами; `links` uid→title и обратные связи отдаются в `BlockDetail`.
- Веб `/kb`: дерево (цвет/иконка/счётчики), Входящие с «Принять»/«Выбрать другую», фильтры в URL (category/q/kind), сетка карточек, пустые состояния; `/kb/[uid]`: шапка с крошками, секции, полноэкранная mermaid (клик), связи-чипы, правая колонка (оглавление упрощено до метаданных, версии с просмотром и откатом, «Обсудить в чате», «Скопировать MD», скачивание .md через `/raw`).
- `seed-demo` (11 блоков в 3 категориях) написан; полный живой прогон фильтров по 10+ блокам не выполнялся (база наполнена живыми блоками, каждый фильтр покрыт тестами на репозитории).
- Отклонения: `/kb/c/[...path]` отдельной страницы нет — категория фильтруется через `/kb?category=…` (та же выборка); редактор дерева в Настройках не делался (категории создаются агентом/`POST /api/kb/categories`); Lighthouse-замер не выполнялся (вне Docker-окружения), доступность проверена ролями/aria в DOM-снапшотах; ⌘K ищет по блокам/источникам без подсветки сниппетов (FTS-сниппеты есть в `/api/search`).
