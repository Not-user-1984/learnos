Визуалы рисуются в браузере. Проверка вместо рендер-сервиса: веб при ошибке отрисовки показывает плашку и сам сообщает серверу (`POST /api/kb/blocks/{uid}/visuals/{idx}/broken` с текстом ошибки) → job один раз просит `illustrator` исправить код по этой ошибке; не вышло — визуал помечается `broken`, кнопка «Перерисовать» остаётся. Предрендеров SVG в `kb/assets/` пока нет; критерии приёмки 2 (часть про предрендеры) и 6 переносятся вместе с сервисом рендера.

**Цель:** из каждого урока автоматически получаются 1–3 красивых визуала, подобранных под содержание (инфографика-шпаргалка, график, архитектурная схема с иконками, схема классов/процесса), плюс автоматическая mind-map блока. По просьбе в чате агент добавляет или перерисовывает визуал. Всё в едином стиле, в чистом виде или «от руки».

## Модель

### В MD-блоке

Новая опциональная секция **«Визуалы»** — после «Схема», перед «Практика». Каждый визуал: подзаголовок-подпись + блок кода с меткой инструмента + (опционально) ссылка на предрендер.

````markdown
## Визуалы

### Как трафик доходит до пода
```mermaid
architecture-beta
  group cluster(logos:kubernetes)[Кластер]
  service svc(server)[Service] in cluster
  service pod(logos:docker-icon)[Pod] in cluster
  svc:R --> L:pod
```
![Как трафик доходит до пода](../assets/blk_1a2b3c4d/1.svg)

### Шпаргалка: Service vs Ingress
```infographic
infographic compare-binary-horizontal-simple
data
  ...
```
````

- Ссылка `![…](../assets/<uid>/<n>.svg)` — предрендер для Obsidian/экспорта; веб-UI её скрывает и рендерит код живьём.
- Секция «Схема» (одна mermaid-схема) остаётся как есть для совместимости; новые уроки кладут основную схему туда, остальные — в «Визуалы».
- `BlockDraft` получает опциональное поле `visuals: list[Visual]`:

```python
class Visual(BaseModel):
    """Визуал блока: код одного из поддерживаемых инструментов и подпись."""
    kind: Literal["mermaid", "infographic", "vis"]
    title: str = Field(max_length=80)
    purpose: str = Field(max_length=160)   # что показывает и почему этот вид
    code: str
```

### Файлы и индекс

- Предрендеры: `kb/assets/<uid>/<n>.svg` (в git — SVG небольшие и нужны Obsidian), PNG — по запросу в `data/renders/` (не в git).
- Таблица `block_visuals(block_uid, idx, kind, title, svg_path, status: ok|broken, error, updated_at)` — индекс; `reindex` пересобирает её из секции «Визуалы».
- Общая палитра и типографика визуалов — один файл `shared/visual-theme.json` (цвета категорий, фон/текст для светлой и тёмной темы, шрифт Geist), его читают и веб, и сервис рендера. Все три инструмента настраиваются из него, чтобы визуалы выглядели как одна система.
- Настройка стиля: `profile.visual.look` = `clean` (по умолчанию) | `handDrawn`. Применяется к Mermaid (`look`) и Infographic (hand-drawn тема); GPT-Vis всегда в чистом виде.

## Сервис рендера

Нужен, чтобы сервер мог **проверить**, что код визуала рисуется, и **предрендерить** SVG/PNG для экспорта и Telegram. Mermaid и AntV требуют браузерного окружения, поэтому — единый headless-рендер:

- `services/renderer/` — небольшой Node-сервис (TypeScript): Playwright (Chromium) + страница, собранная с Mermaid, Infographic, GPT-Vis и иконками; HTTP `POST /render {kind, code, theme: light|dark, look} → {ok, svg | error}`, `POST /render.png` (скриншот SVG), `GET /health`. Один экземпляр браузера, страницы переиспользуются, таймаут рендера 10 с.
- Python-порт `VisualRenderer` (модуль `knowledge`) + HTTP-адаптер; в тестах — `FakeVisualRenderer`. Если сервис не запущен — визуалы сохраняются без предрендера со статусом `unchecked`, UI рисует их живьём; `reindex`/команда `cli render-visuals` догоняет позже.
- Запуск описать в `AGENTS.md` (третий процесс рядом с сервером и вебом; порт по умолчанию 8766, `LEARNOS_RENDERER_URL`).

## Агент `illustrator`

Модуль `knowledge`, роль `structured`, выход — `list[Visual]` (1–3 шт.).

Вход: содержимое блока (понятия, тезисы, практика), фрагменты транскрипта с числами (если есть), категория, `look`, и для каждого инструмента — шпаргалка синтаксиса (`agents/illustrator/cheatsheets/*.md`; для Infographic — список доступных шаблонов с одной строкой «для чего»).

Правила выбора (в промпт):

| Содержание | Вид |
|---|---|
| процесс, алгоритм, жизненный цикл | `mermaid` flowchart / stateDiagram |
| взаимодействие во времени (запрос → ответ) | `mermaid` sequenceDiagram |
| классы, объекты, их поля и связи (ООП) | `mermaid` classDiagram |
| инфраструктура, компоненты системы | `mermaid` architecture-beta с иконками `logos:*` |
| шаги, сравнение, плюсы/минусы, иерархия, таймлайн, набор понятий | `infographic` |
| реальные числа из источника или из моей практики | `vis` |

- **График — только по реальным данным** из источника, транскрипта или вывода команд. Нет чисел — нет `vis`. Данные не выдумываются.
- Не дублировать: два визуала одного вида про одно и то же не делать; основная схема блока уже есть в «Схема» — визуалы её дополняют.
- Подписи по-русски, коротко; в инфографике ≤ 8 пунктов, ≤ 6 слов в заголовке пункта; в схемах ≤ 15 узлов.
- Цикл качества: каждый визуал → `VisualRenderer.render` → при ошибке текст ошибки возвращается модели, до 2 повторов; не исправился — визуал отбрасывается (в лог и `agent_runs`), блок сохраняется без него.

Запуск:

- **Автоматически** после сохранения урока (`kind: lesson`) — job `illustrate_block` (не задерживает `finish_session`); по готовности — `update_block` (версия +1, `reason: «добавлены визуалы»`) и карточка `visuals_ready` в разговор сессии.
- **По запросу** для любого блока: инструменты `add_visual(block_uid, request)` («сделай инфографикой шаги», «график по замерам из практики») и `redraw_visual(block_uid, idx, instruction)` («красивее», «другим шаблоном», «от руки», «добавь Ingress»). Доступны `free_chat`, `quick_reviewer`, `session_tutor` и через MCP. Результат — новая версия блока (откат работает как для любой правки).
- Конспекты (`note`) и runbook-и — только по запросу.

## Задачи

### Бэкенд

- [ ] `Visual` в `BlockDraft`, секция «Визуалы» в сборке/парсинге MD (round-trip без потерь), ревизия Alembic для `block_visuals`, `reindex`.
- [ ] Порт `VisualRenderer`, HTTP-адаптер, фейк; предрендер SVG в `kb/assets/<uid>/`, PNG по запросу; команда `cli render-visuals`.
- [ ] Агент `illustrator` + шпаргалки; job `illustrate_block` после урока; инструменты `add_visual`, `redraw_visual`; карточка `visuals_ready` (тип добавить в zod-схемы карточек).
- [ ] `profile.visual.look`; REST: `GET /api/kb/blocks/{uid}/visuals/{idx}.svg|.png` (из предрендера или через рендер-сервис).
- [ ] Экспорт (этап 6): ZIP содержит `assets/` и ссылки на SVG; склеенный MD — код визуалов + ссылки; Telegram-повторение (этап 8 C) по желанию прикладывает PNG основного визуала к вопросу.

### Сервис рендера

- [ ] `services/renderer/`: Playwright + страница с тремя библиотеками, тема из `shared/visual-theme.json`, регистрация иконок `logos`/`mdi` для Mermaid, `look`; эндпоинты `/render`, `/render.png`, `/health`; тесты на образцах каждого вида (валидный → SVG, сломанный → понятная ошибка).

### Веб

- [ ] Markdown-компонент: рендер блоков кода `infographic` и `vis` (ленивый импорт, клиентские компоненты, ошибка → исходник + плашка «визуал не отрисовался»); Mermaid — тема из общей палитры, иконки, `look`; ссылки-предрендеры `assets/…` скрываются, если рядом есть код.
- [ ] Стриминг в чате: визуалы рисуются по мере генерации (обе AntV-библиотеки это поддерживают; Mermaid — после закрытия блока кода).
- [ ] Страница блока: секция «Визуалы» — галерея карточек (подпись, вид, назначение), полноэкранный просмотр с зумом, скачать SVG/PNG, «Перерисовать» (диалог с инструкцией → `redraw_visual`), переключатель «Чистый / От руки» (локально для просмотра; по умолчанию — из профиля).
- [ ] «Карта блока» (Markmap): сворачиваемая секция наверху страницы блока, строится из заголовков и пунктов на клиенте; работает и для старых блоков; полноэкранный режим.
- [ ] Настройки: стиль визуалов по умолчанию; статус рендер-сервиса (из `/api/health`).

## Критерии приёмки

1. Тесты: выбор видов `illustrator` на FakeLLM (процесс → mermaid, сравнение → infographic, нет чисел → нет `vis`), повтор после ошибки рендера и отбрасывание неисправимого визуала, round-trip секции «Визуалы», старый блок без секции, работа без рендер-сервиса (`unchecked`). Тесты рендер-сервиса на образцах. Команды проверки бэкенда и веба зелёные.
2. Живой сценарий: новый урок по главе тестовой k8s-книги → через ≤ 2 минуты после сохранения у блока ≥ 2 визуала разных видов, оба отрисованы в тёмной и светлой теме, предрендеры лежат в `kb/assets/<uid>/`.
3. В чате «сделай шпаргалку инфографикой по этому блоку» → новый визуал `infographic`, версия блока +1, откат убирает его.
4. Переключатель «От руки» меняет вид Mermaid- и Infographic-визуалов; GPT-Vis остаётся чистым и не ломается.
5. Карта блока (Markmap) открывается для любого блока, включая `blk_87ab94`.
6. ZIP-экспорт, открытый в Obsidian, показывает визуалы картинками.
7. Страница блока с 3 визуалами на ширине 390px: без горизонтальной прокрутки и прыжков вёрстки (зарезервированная высота, ленивый рендер).

- Общая палитра и типографика визуалов — один файл `shared/visual-theme.json` (цвета категорий, фон/текст для светлой и тёмной темы, шрифт Geist), его читают и веб, и сервис рендера. Все три инструмента настраиваются из него, чтобы визуалы выглядели как одна система.
- Настройка стиля: `profile.visual.look` = `clean` (по умолчанию) | `handDrawn`. Применяется к Mermaid (`look`) и Infographic (hand-drawn тема); GPT-Vis всегда в чистом виде.

## Сервис рендера

Нужен, чтобы сервер мог **проверить**, что код визуала рисуется, и **предрендерить** SVG/PNG для экспорта и Telegram. Mermaid и AntV требуют браузерного окружения, поэтому — единый headless-рендер:

- `services/renderer/` — небольшой Node-сервис (TypeScript): Playwright (Chromium) + страница, собранная с Mermaid, Infographic, GPT-Vis и иконками; HTTP `POST /render {kind, code, theme: light|dark, look} → {ok, svg | error}`, `POST /render.png` (скриншот SVG), `GET /health`. Один экземпляр браузера, страницы переиспользуются, таймаут рендера 10 с.
- Python-порт `VisualRenderer` (модуль `knowledge`) + HTTP-адаптер; в тестах — `FakeVisualRenderer`. Если сервис не запущен — визуалы сохраняются без предрендера со статусом `unchecked`, UI рисует их живьём; `reindex`/команда `cli render-visuals` догоняет позже.
- Запуск описать в `AGENTS.md` (третий процесс рядом с сервером и вебом; порт по умолчанию 8766, `LEARNOS_RENDERER_URL`).

## Агент `illustrator`

Модуль `knowledge`, роль `structured`, выход — `list[Visual]` (1–3 шт.).

Вход: содержимое блока (понятия, тезисы, практика), фрагменты транскрипта с числами (если есть), категория, `look`, и для каждого инструмента — шпаргалка синтаксиса (`agents/illustrator/cheatsheets/*.md`; для Infographic — список доступных шаблонов с одной строкой «для чего»).

Правила выбора (в промпт):

| Содержание | Вид |
|---|---|
| процесс, алгоритм, жизненный цикл | `mermaid` flowchart / stateDiagram |
| взаимодействие во времени (запрос → ответ) | `mermaid` sequenceDiagram |
| классы, объекты, их поля и связи (ООП) | `mermaid` classDiagram |
| инфраструктура, компоненты системы | `mermaid` architecture-beta с иконками `logos:*` |
| шаги, сравнение, плюсы/минусы, иерархия, таймлайн, набор понятий | `infographic` |
| реальные числа из источника или из моей практики | `vis` |

- **График — только по реальным данным** из источника, транскрипта или вывода команд. Нет чисел — нет `vis`. Данные не выдумываются.
- Не дублировать: два визуала одного вида про одно и то же не делать; основная схема блока уже есть в «Схема» — визуалы её дополняют.
- Подписи по-русски, коротко; в инфографике ≤ 8 пунктов, ≤ 6 слов в заголовке пункта; в схемах ≤ 15 узлов.
- Цикл качества: каждый визуал → `VisualRenderer.render` → при ошибке текст ошибки возвращается модели, до 2 повторов; не исправился — визуал отбрасывается (в лог и `agent_runs`), блок сохраняется без него.

Запуск:

- **Автоматически** после сохранения урока (`kind: lesson`) — job `illustrate_block` (не задерживает `finish_session`); по готовности — `update_block` (версия +1, `reason: «добавлены визуалы»`) и карточка `visuals_ready` в разговор сессии.
- **По запросу** для любого блока: инструменты `add_visual(block_uid, request)` («сделай инфографикой шаги», «график по замерам из практики») и `redraw_visual(block_uid, idx, instruction)` («красивее», «другим шаблоном», «от руки», «добавь Ingress»). Доступны `free_chat`, `quick_reviewer`, `session_tutor` и через MCP. Результат — новая версия блока (откат работает как для любой правки).
- Конспекты (`note`) и runbook-и — только по запросу.

## Критерии приёмки

1. Тесты: выбор видов `illustrator` на FakeLLM (процесс → mermaid, сравнение → infographic, нет чисел → нет `vis`), повтор после ошибки рендера и отбрасывание неисправимого визуала, round-trip секции «Визуалы», старый блок без секции, работа без рендер-сервиса (`unchecked`). Тесты рендер-сервиса на образцах. Команды проверки бэкенда и веба зелёные.
2. Живой сценарий: новый урок по главе тестовой k8s-книги → через ≤ 2 минуты после сохранения у блока ≥ 2 визуала разных видов, оба отрисованы в тёмной и светлой теме, предрендеры лежат в `kb/assets/<uid>/`.
3. В чате «сделай шпаргалку инфографикой по этому блоку» → новый визуал `infographic`, версия блока +1, откат убирает его.
4. Переключатель «От руки» меняет вид Mermaid- и Infographic-визуалов; GPT-Vis остаётся чистым и не ломается.
5. Карта блока (Markmap) открывается для любого блока, включая `blk_87ab94`.
6. ZIP-экспорт, открытый в Obsidian, показывает визуалы картинками.
7. Страница блока с 3 визуалами на ширине 390px: без горизонтальной прокрутки и прыжков вёрстки (зарезервированная высота, ленивый рендер).
