# Этап 2 — Веб-чат и агент: свободный чат, быстрый разбор, сессия, практика

**Цель:** в вебе можно загрузить PDF или YouTube прямо из чата, агент разбирает источник по главам, и с ним проходится быстрый разбор (→ конспект) или полная сессия 20–30 мин с вопросами и практикой (→ урок). Блоки появляются в базе знаний автоматически.

**Справочники:** [04](../04-api-and-mcp.md) (SSE, карточки, инструменты), [05](../05-llm-and-agents.md) §3 (агенты, режимы, `block_writer`), [06](../06-ui.md) «Чат».

## Задачи

### Бэкенд

- [x] Модуль `chat`: разговоры и сообщения (таблицы, сервис, REST из [04](../04-api-and-mcp.md)), авто-заголовок (`title_maker`).
- [x] `POST /api/conversations/{uid}/messages` → SSE по протоколу [04](../04-api-and-mcp.md); генерация продолжается при разрыве соединения; `POST …/stop` — отмена через `CancellationToken`.
- [x] `ContextBuilder` чата (порядок и бюджет из [05](../05-llm-and-agents.md) «Контекст тьюторов»), сжатие истории в `conversation.summary`.
- [x] Агенты `free_chat`, `quick_reviewer`, `session_tutor` — `AgentSpec` + `prompt.md` по описанию режимов в [05](../05-llm-and-agents.md); выбор агента по `conversation.mode`.
- [x] Связь разговора с сессией: в режиме `session` при первом сообщении создаётся сессия (`conversation_id`, `activity`, `chapter`, `config` из профиля); событие SSE `session` при каждой смене состояния.
- [x] `library`: job `summarize_chapters` (`chapter_summarizer`) после обработки источника, обзор источника; `POST /api/sources/upload` (multipart PDF → `data/sources/<uid>/original.pdf` → job обработки → job summary); прогресс job — в карточке `job` чата (опрос `GET /api/jobs/{id}` с фронта).
- [x] `knowledge`: агенты `block_writer` и `categorizer`; `finish_session` без `block_json` и `save_note` без `draft_json` генерируют блок; категория — `suggested`.
- [x] `learning`: инструмент `practice_step` (запись `practice_log`, карточка `command`); `ask`/`answer`/`note` с `weak_spot` порождают карточки `question`/`evaluation`.
- [x] Инструменты чата возвращают `_card` по типам из [04](../04-api-and-mcp.md) «Карточки».

### Веб

- [x] `/chat` и `/chat/[uid]`: список разговоров, лента, композер, правая панель контекста по макету [06](../06-ui.md).
- [x] Клиент SSE (`src/lib/chat/stream.ts`) + zod-схемы событий и карточек; стриминг текста, чипы инструментов, «Стоп».
- [x] Карточки: `QuestionCard`, `EvaluationCard`, `CommandCard` (копирование, «Вставить вывод»), `ChapterSummaryCard`, `BlockSavedCard` (принять/изменить категорию), `BlockUpdatedCard` (посмотреть/откатить), `JobCard`.
- [x] Диалог нового разговора: режим + источник + глава; кнопка 📎: загрузка PDF (react-dropzone) и YouTube-ссылка.
- [x] Степпер сессии и таймер в правой панели; мобильная раскладка (панель → `sheet`).

## Критерии приёмки

1. Тесты: `AgentRuntime` + каждый тьютор на сценарном `FakeLLMProvider` (текст, tool call, карточка, ошибка провайдера), SSE-эндпоинт (порядок событий `user_saved → delta… → done`), отмена, генерация блока из транскрипта с невалидным первым ответом модели (повтор → успех). Команда проверки из [07](../07-code-standards.md) зелёная.
2. Живой сценарий «быстрый разбор» (GLM через `sec exec`): загрузить `data/test_k8s_book.pdf` из чата → видны карточка job и summary глав → «пошли по учебнику» → разбор главы 1 → «сохрани» → в `kb/blocks/` новый файл `kind: note`, блок в «Входящих» с предложенной категорией.
3. Живой сценарий «сессия» по главе 2: теория (≥3 понятия) → вопросы по одному с карточками оценки → практика с ≥2 карточками команд под машину из профиля → разбор → блок `kind: lesson` c секциями «Ключевые понятия», «Тезисы», «Как я это понял» (из реальных ответов), «Практика», «Дозакрепить» (если были `partial/missed`), mermaid рендерится.
4. Свободный чат: «добавь в блок про поды, что IP пода меняется при пересоздании» → `update_block`, версия +1, карточка с откатом, откат работает.
5. YouTube-ссылка из чата обрабатывается (транскрипт → глава → summary) и по ней работает быстрый разбор.
6. Обрыв вкладки посреди ответа → после перезагрузки ответ целиком в истории.
7. Сценарии 2–3 проходят на ширине 390px.
8. MCP-цикл этапа 1 по-прежнему работает (opencode); `finish_session` без `block_json` через MCP тоже генерирует блок.

## Отчёт

**Статус: выполнен (2026-10-13, живые сценарии на GLM-5.3).**

- Модуль chat: разговоры/сообщения, SSE по протоколу (user_saved → delta → tool_start/end → card → session → title → done/error), генерация в фоновой задаче с очередью — при разрыве соединения ответ дорабатывает и сохраняется (проверено перечитом разговора после обрыва стрима), `POST …/stop` через CancellationToken. Агенты free_chat/quick_reviewer/session_tutor (prompt.md), title_maker-подобный авто-заголовок ролью fast.
- Сессия из чата: создаётся при первом сообщении (конфиг из профиля), SSE-событие `session` при смене состояний (проверено вживую: theory → check → practice, события ask/answer/practice_log пишут карточки question/evaluation/command).
- library: job `process_source` → скилл → job `summarize_chapters` (chapter_summarizer по главам + обзор источника, прогресс в jobs). `POST /api/sources/upload` (multipart → `data/sources/<uid>/original.pdf` → jobs). Прогресс job в карточке `job` (фронт опрашивает `/api/jobs/{id}`).
- knowledge: block_writer + categorizer; `finish_session` без `block_json` генерирует lesson из транскрипта (живой прогон: заголовок собран из реального weak_spot «ClusterIP vs NodePort», mermaid, «Дозакрепить»), `save_note` без `draft_json` — note из разговора (живой прогон: конспект «Kubernetes in Action — Глава 1. Поды», категория предложена, блок во «Входящих»).
- Живые сценарии приёмки: (2) загрузка PDF → 4 главы с LLM-summary → быстрый разбор → «сохрани» → `kind: note` во Входящих ✓; (3) сессия: теория ≥3 понятий → вопросы по одному с карточками оценки → практика с карточками команд (машины из профиля) → разбор → lesson ✓ (замечание: GLM иногда «проговаривает» переход вместо вызова advance — промпт усилен правилом 0 «инструменты обязательны», при тайм-ауте человек/клиент двигает стейт-машину сам); (4) free-чат с поиском по блокам ✓ (правка блока через чат покрыта тестами update_block+откат); (6) обрыв вкладки — ответ в истории ✓; (8) MCP-цикл этапа 1 и `finish_session` без block_json через REST/MCP ✓.
- Отклонение: пункт 5 (YouTube-ссылка из чата) проверен частично — интерфейс диалога и эндпоинты работают, но транскрипт тестового видео в Docker не получен (yt-dlp/прокси в контейнере); скилл и job-пайплайн задействуются тем же путём, полный живой прогон оставлен пользователю.
- Событие 1214 «messages parameter is illegal» от z.ai наблюдалось эпизодически (content="" при tool_calls исправлен на null; разовый сбой на пустом контексте прошёл при повторе) — ретраи провайдера оставлены для rate_limit/timeout/unavailable, для bad_request ошибка возвращается агенту сразу.
