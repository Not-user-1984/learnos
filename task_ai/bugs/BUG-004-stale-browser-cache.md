# BUG-004 — после деплоя вкладка сидит на старой сборке

**Статус:** fixed в [T-044](../tasks/T-044-chat-incident-fixes.md) · найдено 2026-10-28 · воспроизведено на проде

## Симптом

После деплоя пользователь видит СТАРЫЙ интерфейс: нет кота, нет меню ссылок,
нет бейджа работы — «всё падает и исчезает». Обычный reload не всегда помогал.

## Воспроизведение

Вкладка на /chat отдавала старый HTML из кэша браузера при живом новом SSR
(curl SSR содержал новые элементы). Помогло только ?_r=… (обход кэша).
У приложения есть PWA-слой; на http-origin сервисворкер неактивен, но кэш
HTML в браузере агрессивен.

## Фикс (T-044)

`next.config.ts` → `headers()`: документы (`/:path*`) — `Cache-Control: no-cache`
(браузер всегда переспрашивает HTML), `/_next/static/*` —
`public, max-age=31536000, immutable` (хешированные чанки бессрочные). Правила
попадают в routes-manifest → применяются и standalone-сервером в Docker (прод
отдаёт веб напрямую из контейнера, без nginx-прослойки). Проверено curl -I по
собранному вебу: /chat → `no-cache`, чанк → `immutable`.

Service worker (`public/sw.js`) уже безопасен: кэширует только манифест и иконки,
страницы всегда идут в сеть — на http-origin он неактивен, но и на https старый
HTML из кэша не отдаст.

## Костыль до выката

Ctrl+Shift+R (обход кэша).
