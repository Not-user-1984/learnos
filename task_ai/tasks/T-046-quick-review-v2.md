## Что нужно

Быстрый разбор книги (агент quick_reviewer) должен стать полноценным режимом
обучения рядом с сессиями: сессия — углублённое изучение, быстрый разбор —
быстрое прохождение книги по главам. Сейчас разбор — «голый» чат: без видимого
прогресса, сплошным текстом, конспект только по главе, проверка знаний только
по явной команде.

Данные для прогресса уже есть: `mark_chapter_done` двигает курсор активности
(`cursor_chapter`/`total_chapters`), главы отмечаются. Не хватает UI и охвата.

## Этапы (делать по порядку, каждый — отдельный коммит/порция)

### Э1. Прогресс быстрого разбора книги (приоритет внутри эпика)

- Статус-бар книги в разговоре разбора: сколько глав пройдено / всего,
  какая текущая; видно, какие главы уже разобраны.
- Прогресс разбора — отдельно от прогресса сессий (два вида прогресса
  не смешиваются: сессия = углублённо, разбор = быстро).
- Прогресс переживает уход из разговора и возврат (хранится в БД — уже есть,
  важно показать). Красиво по DESIGN.md; финальную визуальную полировку
  статуса-бара делает ZCode (hallmark).

### Э2. Визуальные блоки в быстром разборе

- Вывод разбора — блочный, как в сессии (карточки-блоки: «Главное за 30
  секунд», «Ключевые понятия», «Что применимо»), а не сплошной markdown.
- Уточнить на старте у пользователя, если формулировка «визуальные блоки»
  означает что-то другое (например, визуалы блоков из T-009).

### Э3. Конспект по всему разговору разбора

- Кнопка/команда «Сделать конспект» в разборе работает по ВСЕМУ разговору
  (все разобранные главы), а не только по текущему блоку/главе: агент
  проходит разговор целиком и предлагает превью конспекта (preview_note
  с охватом всех разобранных глав).

### Э4. Проверка знаний по блокам в разборе

- Режим «проверка знаний» в разборе: включил — при разборе каждого блока
  агент задаёт вопросы по этому блоку (сейчас закрепление — только по явной
  команде «закрепим/проверь меня» после прохождения).

## Заметки

- Эпик на несколько порций: передавать агенту-разработчику по одному этапу,
  не всё сразу; Э1 — первым.
- Связка: карточка кандидатов research (T-014 Э3) — соседняя UX-работа
  по карточкам, может переиспользовать наработки T-045.

### Э1 — решения (2026-10-28)

- Прогресс разбора = курсор активности разговора (`cursor_chapter`/
  `total_chapters`), без новой таблицы: данные уже двигались
  `mark_chapter_done`. Пройдено = `cursor - 1`, текущая = `cursor`.
- Отдельно от сессий: сессия — панель стейт-машины справа (шаги
  theory→…→done), разбор — полоса книги под шапкой; обе сущности
  сосуществуют в одном разговоре, не смешиваясь.
- API: `review_progress` в GET разговора (None без активности); SSE-событие
  `review_progress` после тулов `REVIEW_TOOLS` (mark_chapter_done,
  finish_session — finish_session тоже двигает курсор) — как `session`
  после SESSION_TOOLS.
- Видео/материалы с total ≤ 1 полосу не показывают (данные отдаются
  честными, скрывает клиент) — у видео нет глав для прохождения.
- До 30 глав — сегменты по главам (видно разобранные и текущую), больше —
  полоса с заполнением; токены DESIGN.md (bg-primary/bg-muted), финальная
  полировка — ZCode (hallmark).
- Библиотека у источника уже показывает «Изучение идёт: глава N из M» —
  согласовано по данным (одна активность), главный экран — разговор.

### Э2 — решения (2026-10-29)

- «Блочный вывод» = структурированная карточка разбора (как NoteDraftCardView),
  а не визуалы T-009: пользователь видел карточки в сессии и хочет тот же вид
  в быстром разборе (уточнено заказчиком).
- Инструмент `show_chapter_review` по образцу offer_action/offer_replies:
  валидация pydantic (key_points 3–5, concepts 1–8, applicable 1–5,
  questions 1–2, media=chapter|video), `_card` → SSE `card` → cards_json —
  история показывает разбор живой карточкой, новой сущности в БД нет.
- Инструмент у quick_reviewer И root: новые разговоры всегда root, интент
  «review» единого входа ведёт root сам (без этого карточка не появлялась бы
  нигде, кроме legacy-режима quick). free_chat/session_tutor инструмент не
  получили — разбор не их жанр.
- Промпт: карточка — итог разбора, текст — только 2–3 строки сопровождения;
  «подробнее» и углубления — обычный markdown без новой карточки. Видео —
  та же карточка с media="video", title = название видео.
- Карточка НЕ запись в базу знаний: конспект по-прежнему preview_note →
  апрув (Э3 конспекта по всему разговору — не трогали).
- Веб: секции «Главное / Ключевые понятия / Что применимо / Вопросы на
  подумать», термины жирным, только семантические токены (bg-card, muted,
  primary), работает во всех трёх темах; media меняет иконку и надпись
  («Разбор главы»/«Разбор видео»).
