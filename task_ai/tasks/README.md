# task_ai/tasks — система задач разработки

Здесь живёт бэклог агента-разработчика LearnOS. Одна задача — один файл.

## Каталоги

| Каталог | Что лежит |
|---|---|
| `tasks/` | открытые задачи: `active` (берём в работу), `idea` (хотим, но не сейчас), `on-request` (только по явной просьбе пользователя) |
| `archive/` | выполненные задачи и отчёты по этапам — история «что и когда сделано» |
| `../stages/` | ТЗ-этапы, ещё не переведённые в задачи (после выполнения этап переезжает в `archive/`) |

## Формат задачи

```markdown
---
id: T-012
title: Короткое название
status: active   # active | idea | on-request | done (done = сразу в архив)
priority: high   # high | medium | low
from: Этап 8A / backlog / спонтанная задача пользователя
created: 2026-10-17
---

## Что нужно
…

## Критерии готовности
- [ ] …

## Заметки
…
```

## Воркфлоу агента (обязателен)

1. **Взял задачу** из `tasks/` (статус `active`, сверху самая приоритетная). Нужной нет — уточни у пользователя, потом создай файл.
2. **Разобрался**: прочитал README корня, ARCHITECTURE.md и файлы ТЗ, указанные в `from`.
3. **Сделал**: код + тесты (новое поведение покрывается тестами всегда), `ruff`/`import-linter`/`pytest` на сервере, `tsc`/`eslint`/`build` на вебе — всё зелёное.
4. **Выкатил**: коммит (одно логическое изменение = один коммит, сообщение в стиле репо) → `git push origin main` → автодеплой на CT 132 (до ~5 мин) → убедился по `journalctl -u learnos-deploy.service` и `/api/health`, что прод поднялся.
5. **Закрыл**: `git mv` файла задачи в `archive/` с датой закрытия, обновил `archive/README.md` одной строкой, при необходимости обновил STATUS (текущий статус)/README/ARCHITECTURE/AGENTS (документация обновляется **после** успешного деплоя, не до).
6. Если задача не доведена до конца — статус `idea` или заметка «где остановился» в файле задачи. Полусделанное не помечается done.

## Правила

- Режим работы — автономный (решение пользователя 2026-10-22): агент сам делает, тестит, выкатывает, проверяет прод и закрывает таску. Не ждать подтверждений по ходу и приёмки пользователя перед закрытием — отчёт присылается постфактум с готовым результатом.
- Пользователь сказал «сделай X» → это задача: создай файл (если X не мгновенный багфикс) и работай по воркфлоу.
- Копилка идей без конкретики — `idea`, не `active`.
- Архив не редактируется задним числом; правки истории — только новым файлом/коммитом.
