## Что нужно

У пользователя 4 ключа z.ai (ZAI_API_KEY, ZAI_API_KEY_2..4 в macOS Keychain через
`sec`). Сейчас LLM-слой принимает один (`server/config/llm.yaml: api_key_env:
ZAI_API_KEY`) — исчерпание квоты ключа роняет весь чат до сброса окна. Нужна
цепочка: при ошибке квоты/лимита система переходит на следующий ключ.

1. **Конфиг**: `llm.yaml` — у провайдера помимо `api_key_env` новый список
   `api_key_envs: [ZAI_API_KEY, ZAI_API_KEY_2, ZAI_API_KEY_3, ZAI_API_KEY_4]`
   (приоритет: список, затем одиночный `api_key_env` как fallback для
   совместимости). Пустые/отсутствующие env пропускаются, дубликаты убираются,
   порядок сохраняется = порядок цепочки. `ModelRouter`/Settings собирают пул.
2. **Провайдер** (`server/app/llm/providers/openai_compat.py`): ротация ключей —
   держим «текущий рабочий» индекс (sticky); при ошибке квоты/лимита
   (HTTP 429, 401/403, сообщения вида «превышен лимит»/«insufficient»/«quota»)
   помечаем ключ в cooldown (например 10 минут, настройка в Settings) и
   ретраим запрос следующим ключом из пула; все ключи в cooldown — LLMError с
   понятным сообщением (ближайший сброс). Сетевые ошибки/5xx — не ротация
   (обычный ретрай, если он уже есть). Идентификация ключа в логах — по
   порядковому номеру (zai#2), значение не логировать никогда.
3. **Health**: `/api/health` — `llm_configured: true` при ≥1 ключе; приятно:
   `llm_keys: N` (сколько в пуле, без значений).
4. **Дока**: README/AGENTS — секция env: дополнительные ключи опциональны,
   цепочка в порядке списка.

## Решения и где смотреть (для ревью)

- `server/config/llm.yaml` — `api_key_envs: [ZAI_API_KEY, ..._2, _3, _4]` у zai;
  одиночный `api_key_env` в коде остался fallback-совместимостью.
- `server/app/llm/router.py` — `_collect_api_keys(spec)`: порядок списка, пустые/дубли
  env сняты; `status()` отдаёт `keys: N` (0 для keyless, False+причина если вся цепочка пуста).
- `server/app/llm/providers/openai_compat.py` — пул ключей в конструкторе
  (`api_keys`, `cooldown_seconds`, `monotonic` — порт для тестов времени);
  `_pick_key` (sticky, по кругу, LLMError «ближайший сброс через N мин» когда все
  в cooldown), `_cooldown_key` (лог `zai#N`, без значения), `_with_key_rotation`
  оборачивает complete и открытие стрима. Ротация только на `rate_limit`/`auth`;
  403 (PermissionDeniedError) и quota-маркеры в сообщении (quota/insufficient/
  «превышен лимит») классифицируются `_map_error` в эти коды. Сетевые/5xx —
  прежний ретрай тем же ключом (`_RETRYABLE` без rate_limit). Клиенты кэшируются
  на (event loop, индекс ключа).
- `server/app/kernel/config.py` — `llm_key_cooldown: int = 600` (LEARNOS_LLM_KEY_COOLDOWN);
  `bootstrap.py` прокидывает в ModelRouter.
- `/api/health` (`main.py`) — новое поле `llm_keys: N`.
- Тесты: `server/tests/unit/llm_keychain_test.py` (12) — фейковый транспорт
  с поведением по значению ключа-заглушки (k1/k2), заглушка monotonic-времени;
  + строка `llm_keys == 0` в `tests/api/test_rest.py`.
- Дока: README (LLM-абзац + ключи прода), AGENTS.md (блок после docker compose).
