## Что нужно

Любой материал, созданный пользователем, удаляется из UI с диалогом подтверждения. Сейчас удаление есть только у части сущностей, а API-эндпоинты и UI не согласованы.

Инвентарь на 2026-10-22 (проверено по коду):

| Сущность | API DELETE | UI удаление |
|---|---|---|
| Источник (library) | ✓ `DELETE /api/sources/{ref}` | ✓ список библиотеки, с диалогом; при живых блоках сервер запрещает |
| Курс | ✓ `DELETE /api/courses/{ref}` (элементы каскадом) | ✗ |
| Разговор | ✓ `DELETE /api/conversations/{uid}` | ✗ |
| Кастомный агент | ✓ `DELETE /api/tuning/agents/{name}` | ✓ настройки |
| Внешний MCP | ✓ `DELETE /api/mcpext/{name}` | ✓ настройки |
| Блок БЗ | ✗ | ✗ |
| Категория БЗ | ✗ | ✗ |
| Активность | ✗ | ✗ |
| Сессия | ✗ | ✗ |

Скоп:

1. **API** — новые DELETE-эндпоинты:
   - `DELETE /api/kb/blocks/{uid}` — блок + версии (`block_versions`) + md-файл в `kb/` + поисковый индекс (аналогично правке блока: файл и индекс обновляются);
   - `DELETE /api/activities/{ref}` и `DELETE /api/sessions/{ref}` — обучение.
2. **UI** — кнопка «удалить» везде, где сущность показывается:
   - курс: карточка в списке `/courses` + страница курса;
   - разговор: заголовок чата (или список разговоров);
   - блок БЗ: страница блока / карточка;
   - активность: место показа активности (study-flow).
3. **Подтверждение** — обобщить паттерн из `library-browser.tsx` в один переиспользуемый компонент (`ConfirmDeleteDialog`), а не копировать диалог в каждую страницу.

## Решить перед стартом

- Политика зависимостей: предложение — как с источниками (запрет при живых зависимостях, понятная ошибка в диалоге), без каскадов в v1:
  - сессия не удаляется, если по ней создан блок БЗ;
  - активность не удаляется, если у неё есть сессии (или каскад «активность → её сессии без блоков»?);
  - блок не удаляется, если на него ссылается элемент курса.
- Удаление категории: только пустая (без подкатегорий и блоков) — минимальный скоп, можно вынести в отдельную задачу или пропустить.
- Удаление блока БЗ не нарушает ядро продукта (блок *рождается* только через сессию — про удаление правило не говорит), но подтверждение должно явно предупреждать, что знания пропадут.

## Критерии готовности

- [ ] `DELETE` для блоков БЗ, активностей, сессий; тесты API (создать → удалить → 404, зависимость → 409/400)
- [ ] удаление блока вычищает версии, md-файл, индекс (проверить поиск после удаления)
- [ ] UI: удаление курса, разговора, блока, активности — с диалогом подтверждения (единый компонент)
- [ ] сервер отклоняет удаление при живых зависимостях; UI показывает ошибку из ответа
- [ ] сервер: `ruff`/`import-linter`/`pytest`; веб: `tsc`/`eslint`/`build` — зелёные

## Заметки

- Готовые DELETE на сервере: `server/app/modules/{library,courses,chat,tuning,mcpext}/api.py`; веб-клиент: `apiDelete` в `web/src/lib/api.ts:45`.
- Диалог-паттерн подтверждения: `web/src/components/library/library-browser.tsx` (Dialog + destructive-кнопка, состояние `removing`/`deleting`).
- Каскад `delete_course` уже удаляет элементы, источники/блоки не трогает — образец семантики.
