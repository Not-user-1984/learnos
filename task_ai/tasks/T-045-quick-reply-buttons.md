## Что нужно

Когда агент в диалоге что-то спрашивает или предлагает варианты («дальше /
подробнее / сессия по главе?», «сохранить конспект?», «перейти к следующей
главе?»), пользователь печатает ответ руками. Нужно: к таким вопросам агент
прикладывает сгенерированные кнопки — короткие варианты ответа; клик = отправка
сообщения. Писать «дальше» текстом больше не нужно.

Контекст: механизм карточек уже есть — action_offer (T-036) с кнопками Да/Нет
и блокировкой после клика (T-044). Для вариантов «дальше/подробнее/сессия»
нужна карточка с произвольным набором коротких ответов (quick replies),
не только Да/Нет.

## Что сделать

- Карточка `quick_replies` (или расширение action_offer): список коротких
  вариантов (2–4), клик отправляет текст варианта как обычное сообщение,
  кнопки блокируются после клика (как в T-044: «отправлено — агент работает…»).
- Канал доставки: SSE-карточки к сообщению агента (уже существующий механизм
  live-cards) — агент прикладывает варианты структурированно, UI не угадывает
  вопросы парсингом текста.
- Промпты агентов (quick_reviewer, session_tutor, root): в местах, где агент
  предлагает выбор (п.3 quick_reviewer «дальше / подробнее / сессия», конец
  главы, предложение конспекта) — прикладывать карточку вариантов.
- Дизайн — по DESIGN.md, токены, обе темы; компактно, над инпутом или в теле
  сообщения — на усмотрение разработчика + визуальная полировка ZCode.

## Критерии готовности

- [ ] В быстром разборе после главы агент предлагает «дальше / подробнее /
      сессию» кнопками — клик отправляет ответ, печатать не нужно.
- [ ] Предложение конспекта/сохранения тоже с кнопками.
- [ ] Кнопки блокируются после клика (нет дублей, T-044-поведение).
- [ ] Карточки не ломают обычные ответы без вариантов; старые разговоры
      отображаются без ошибок.
- [ ] Тесты: сервер — карточка доходит в SSE; веб — рендер и клик.
