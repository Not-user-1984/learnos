## Баг

Книга src_34c882b6 на проде: в режиме PDF любая глава открывается с титульной страницы, «следующая глава» тоже сбрасывает на титульник. Отображение работает, переход на страницу главы — нет.

## Корень (подтверждается воспроизведением пользователя + механикой)

Iframe с нативным вьюером не прыгает на страницу: фрагмент `#page=N` нативный вьюер Chrome игнорирует внутри iframe (надёжен только в топ-уровне вкладки), смена только фрагмента в src не перезагружает iframe (HTML-навигация не происходит при изменении одного fragment), Safari — не работает вообще. Проверка T-026 смотрела атрибут src (там `#page=6`), а не реальный рендер. Дополнительно в Electron webview (встроенный браузер) нативный PDF-плагин не работает вовсе.

## Решение

Встроенный pdf.js-просмотрщик (canvas-ренер) вместо iframe:

- `pdfjs-dist` в бандл, воркер + cmaps + standard_fonts копируются в `public/pdfjs/` скриптом (prebuild/predev, не в git), `GlobalWorkerOptions.workerSrc`.
- Компонент `pdf-viewer.tsx`: страницы на canvas, ленивый рендер видимых ±2 (IntersectionObserver), «fit-width», зум ±, страница ±, текущая/всего, скролл колёсиком. Прыжок к странице главы — скролл к странице без перезагрузки документа (документ один на источник, главы проматываются). Текущая страница наружу (индикатор «глава N · страница M»).
- «В новой вкладке» (нативный вьюер) остаётся fallback-ссылкой.
- Bonus: canvas-рендер работает в Electron webview, где нативного плагина нет.

Сервер outline — надёжность для всех книг: промах по title → страница предыдущей сматченной + 1 (clamp); api-тесты на TOC без закладок, вложенные уровни, промахи. Новые книги покрываются автоматически (outline из файла по запросу, кэш инвалидируется на reprocess).

## Критерии готовности

- [x] Воспроизведение зафиксировано (баг пользователя на проде: все главы → титульник; механика: fragment в src не перезагружает iframe, нативный вьюер игнорирует #page внутри iframe, Safari вообще, Electron — плагина нет)
- [x] PdfViewer: глава 2 → рендер со страницы 4; «следующая глава» → 8 (без перезагрузки документа, индикатор «PDF · глава 3 · стр. 8»)
- [x] Ленивый рендер (в момент проверки в DOM 2 канваса из 12; коридор 700px)
- [x] Серверные тесты outline на формы TOC (без закладок, вложенные уровни, промах → prev+1); pytest/ruff/format/lint-imports зелёные
- [x] lint/tsc/build зелёные; деплой, прод-проверка живьём, задача в архиве

## Реализация

- `web/src/components/library/pdf-viewer.tsx`: pdfjs-dist 6.4 (динамический импорт — SSR не касается), воркер/cmaps/standard_fonts → `public/pdfjs/` скриптом `scripts/copy-pdf-assets.mjs` (predev/prebuild, в .gitignore); canvas-страницы в ленивом коридоре (IntersectionObserver, вне коридора канвасы снимаются), fit-width + зум ±10% + «по ширине», стр.±/счётчик, переход к странице главы скроллом (документ грузится один раз на источник), индикатор текущей страницы наружу (pagechanging по скроллу).
- `reader.tsx`: PdfViewer вместо iframe; ссылка «В новой вкладке» переехала в тулбар вьюера (нативный вьюер — fallback).
- Сервер `chapter_pages`: промах по title → страница предыдущей сматченной + 1 (clamp по total); тесты: без закладок → все 1; вложенный TOC (level 1+2) → матч по level 1; кейс «только подразделы без level-1» fitz-ом не генерится (set_toc требует первую закладку уровня 1) — ветка оставлена по аналогии со сплиттером для живых PDF.
