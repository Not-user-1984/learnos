## Что изменилось (по багам)

- **BUG-001** (сервер): `ChatService.ensure_idle` — занятый разговор → HTTP 409 до
  SSE и до сохранения сообщения (`modules/chat/service.py`, `modules/chat/api.py`);
  SSE-pump несёт код ошибки приложения (`conflict`/`not_found`), не безликий `internal`.
  Тест: `test_send_message_while_busy_is_409_without_duplicate`.
- **BUG-001** (веб): карточка action_offer — кнопки блокируются после клика с
  «отправлено — агент работает…» (`cards.tsx`); при 409 оптимистичный бабл
  откатывается, инлайн-подсказка «агент уже работает» + toast.info вместо красного
  баннера (`chat-view.tsx`); HTTP-ошибки до стрима парсят пояснение из JSON-тела
  (`lib/chat/stream.ts`).
- **BUG-002** (веб): клик по тексту YouTube/PDF-ссылки — preventDefault + меню
  действий, «Открыть в новой вкладке» первым; модификаторные клики нативно
  (`markdown/ActionLink.tsx`).
- **BUG-003** (сервер): колонка `agent_runs.current_tool` (миграция 0011),
  рантайм пишет label текущего инструмента, `active_runs` отдаёт `runs[].current`
  (`agent/recorder.py`, `agent/runtime.py`, `agent/infra_tables.py`).
  Тест: расширение `test_agent_state_working_during_generation`.
- **BUG-003** (веб): бейдж «агент работает: root · шаг N · <текущий инструмент>» +
  кнопка «Остановить» (существующий `/stop`) рядом (`chat-view.tsx`, `lib/types.ts`).
- **BUG-004** (веб): `headers()` в `next.config.ts` — документы `Cache-Control:
  no-cache`, `/_next/static` — `immutable`. Проверено curl -I на сборке
  (`next start`) и в `routes-manifest.json` (его применяет standalone-сервер Docker).
- **BUG-005** (сервер): `_parse_iso` → naive UTC, `_utcnow_naive()` для cutoff
  (`agent/recorder.py`). Тесты: `tests/unit/recorder_test.py` (3-часовой running
  не живой; naive created_at не роняет сравнение).

## Заметки

- Корень BUG-001 («тихие дубли»): проверка занятости стояла в `_reply_stream`
  ПОСЛЕ вставки user-сообщения — сообщение сохранялось навсегда, а SSE-error
  вкладка пользователя (сидевшая на старой сборке, BUG-004) не показывала.
  Починено переносом проверки до вставки + явным 409.
- `ensure_idle` проверяет и `_running`, и `recorder.active_runs` — консистентно
  с `_check_resume` (resume переиспользует тот же метод, текст конфликта единый).
- Карточка action_offer после клика остаётся заблокированной до перезагрузки
  страницы: один оффер = один ответ; повторное согласие после reload — уже
  осознанное действие пользователя, не даблклик.
- Порядок правил headers() в next.config важен: общее `/:path*` первым,
  `/_next/static` перебивает его для статики (проверено фактическими заголовками).
- Service worker трогать не понадобилось: он кэширует только манифест/иконки,
  страницы всегда из сети (безопасно и на https-origin).
- test_sse/test_migrations обновлены под новые коды ошибок SSE и голову
  миграций (0011) — это фиксация изменившегося контракта, не подгонка.
