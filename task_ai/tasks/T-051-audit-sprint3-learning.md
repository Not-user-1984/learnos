## Что нужно

Качество учебного ядра из аудита (раздел C) + P1-дефекты:

- **C. Модель знания и повторений**: таблицы `concepts` (из BlockDraft.concepts),
  `assessments` (каждый фейнман-вопрос/ответ структурно, сейчас только в transcript_json),
  `review_items` на уровне понятия/вопроса (SM-2 по concept_uid), `learner_state` по темам;
  фейнман-гейт: weak_spots блока детерминированно ⊇ вердикты partial/missed; пометка блока
  `verified`; чередование тем в reinforce, retrieval-first, вопросы на применение,
  рубрика оценки в review_examiner (корректность/полнота/пример).
- **R-17 SRS**: лапс (reps=0) игнорирует due и сразу в очереди — остывание; элементы
  заводятся только для блоков с weak_spots ≥1 — зрелое знание не закрепляется;
  `answer_review` не передаёт вопрос экзаменатору (оценка «относительно блока») →
  `question` в AnswerArgs; мёртвый код (ReviewService.ask, TelegramBridgeMessenger,
  Telegram-дайджесты) — реализовать или удалить + поправить доки; SM-2: ease на reps 0/1,
  `int(ease*10)` → round.
- **R-18 Честная сессия**: TRANSITIONS допускают finish без единого ask/answer → guard в
  advance/finish (count(answer) ≥ questions_total или явный skip_reason);
  `save_note`/`preview_note` создают блоки без сессии — решить против «ядро: блок только
  через сессию» (легитимный kind=note: различать «проговорённое» и «конспект», поле verified).
- **R-19 Поиск**: FTS AND по точным токенам без стемминга → OR/bm25, префиксы `слово*`,
  стоп-слова, деградация по числу слов при нуле, snowball-стеммер при индексации и запросе;
  reindex_chapters полная пересборка на каждое событие → инкремент по source_uid;
  индексация первых 60k главы → чанки по ~2-3k с chapter_id+chunk_idx; поиск по
  summary/key_points/категории блока; следующий шаг — sqlite-vec + RRF.
- **R-20 Ингест книг**: листинги кода схлопываются в строку (моноширинные спаны → fenced);
  `\u00ad` удалять, склеивать переносы слов; заголовки секций из sections_json на страницах;
  границы глав по y-координате заголовка; fallback без закладок; `_run_summarize` —
  map-reduce по чанкам (не первые 12k), параллельный пул, summary_status по главе;
  лимит upload + дедуп по sha256.

## Критерии готовности

- [ ] Фейнман-вопросы/ответы хранятся структурно; слабые ответы автоматически в weak_spots
- [ ] Сессию нельзя закрыть без проговора (или с явным skip_reason)
- [ ] Повторения: лапс остывает, блоки без weak_spots тоже повторяются по расписанию
- [ ] Поиск «как работает pod» находит «поды/pods», релевантное ранжирование; переиндексация
      инкрементальная
- [ ] Код в главах книги сохраняет форматирование; summary главы не по первым 12k
- [ ] Тесты на всё вышеперечисленное, прод зелёный
