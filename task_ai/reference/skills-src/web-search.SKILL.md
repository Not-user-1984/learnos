# web-search: поиск в интернете, который не ломается о сеть

Задача скилла — получить **честные результаты поиска** на любой машине с любой
сетью (домашняя, корпоративная, VPN-выход), отличив «не нашлось» от «движок
отравлен/заблокирован».

## Когда запускать

- Любой запрос «поищи в интернете», «найди», «чья это цитата/фраза».
- `webfetch`/curl по поисковику вернул transport error, 429, капчу или мусор.
- Поисковик отвечает не на том языке / нерелевантным (отели вместо цитаты).

## Главные правила

1. **Не доверяй одному движку.** Минимум два источника на любой вывод.
2. **Проверяй язык/релевантность результатов.** Если на русский запрос приходят
   иврит/китайский/немецкий — движок отравлен (гео по IP-выходу), НЕ показывай
   это пользователю как «найдено». Пометь движок мёртвым, бери следующий.
3. **«Ноль точных совпадений» — это ответ.** Кавычечный запрос, все живые движки
   ушли в «похожие» результаты → фраза не индексирована (стрим/голос/личный чат).
   Так и докладывай.
4. **VPN-выход = зона риска.** Если системный DNS 10.x / резолвится мало хостов —
   скажи пользователю: «поиск через VPN деградирует, лучше выключить» — и жди
   решения, либо работай с тем, что живо.

## Порядок работы

### ⚡ Инструмент first: `web_research.py` (детерминированный конвейер)

Прежде чем писать скрипты руками — прогони тулзу. **Режим турбо = CDP-демон**:
браузер живёт в фоне с тёплыми cookies, каждый запуск подключается за ~0.2с,
запросы и резолв идут параллельно вкладками. Поиск ≈ 10 сек (против 40+ холодных).

```bash
# один раз за сессию (или добавить в автозапуск):
python3 ~/my_dev/radmipa-skills/tools/web_research.py daemon start   # поднять демона :9222
python3 ~/my_dev/radmipa-skills/tools/web_research.py daemon stop

# работа (если демон жив — автоматом CDP-turbo, нет — холодный fallback):
python3 ~/my_dev/radmipa-skills/tools/web_research.py probe
python3 ~/my_dev/radmipa-skills/tools/web_research.py search "запрос" --top 6
python3 ~/my_dev/radmipa-skills/tools/web_research.py read URL1 URL2
python3 ~/my_dev/radmipa-skills/tools/web_research.py research "тема" --read 4
```

Тулза сама делает: параллельный батч запросов по аспектам → фильтр мусора
(домены-помойки, AI-заглушки) → параллельный резолв `google.com/goto`-редиректов →
дедуп по реальным URL → скоринг (авторитетные домены + свежесть) → параллельное
чтение топа с extraction основного контента → дайджест.
Капча: `--gui`, юзер кликает, cookies липнут в профиль демона.

Ручные скрипты (ниже) — только если тулза не покрыла кейс.

### Шаг 1. Диагностика сети (10 секунд)

```bash
# Кто резолвится? (DNS-блок = движок недоступен на этом выходе)
for h in yandex.ru google.com bing.com html.duckduckgo.com mojeek.com ecosia.org; do
  python3 -c "import socket; socket.gethostbyname('$h')" 2>/dev/null && echo "$h OK" || echo "$h FAIL"
done
scutil --dns 2>/dev/null | grep nameserver | head -3   # DNS 10.x = корп. VPN
```

- Все OK → нормальная сеть, начинай с Яндекса (лучший для ru), фолбэк Google.
- Частичные FAIL → работай только по живым, пропуская мёртвые.
- DNS 10.x + массовые FAIL → VPN-выход: предупреди пользователя (см. правило 4).

### Шаг 2. Цепочка движков (в порядке приоритета для ru-запросов)

| # | Движок | Инструмент | Признак успеха | Признак смерти |
|---|--------|-----------|----------------|----------------|
| 1 | Яндекс | browser-pilot (exec-скрипт) | `li.serp-item` с русскими тайтлами | `showcaptcha` в URL, ERR_NAME_NOT_RESOLVED |
| 2 | Google | browser-pilot + consent-клик | `h3` с русскими тайтлами | `/sorry/` (капча), 429 |
| 3 | DDG html/lite | curl `-G --data-urlencode` | `result__a` | HTTP 000 / пусто |
| 4 | Bing | curl или browser-pilot | релевантные `li.b_algo` | **результаты не на языке запроса** = отравлен, вон |
| 5 | Mojeek/Ecosia/SearX | curl | органик-блоки | HTTP 000 |

**Критично для curl:** только `curl -s -G "https://…" --data-urlencode "q=ЗАПРОС"`
(кавычки в запросе — `\"`), с браузерным User-Agent. GET с телом/сырыми
параметрами даёт 415/мусор. DDG-парсинг: `class="result__a"` (html) / `rel=nofollow`
ссылки (lite).

**Bing-ловушка:** он почти всегда «отвечает» — но при VPN-выходе выдаёт
гео-мусор (отели/пин-коды/Zhihu). Всегда сверяй язык результатов с языком
запроса. Несовпал → `continue` по цепочке, а не «вот результаты».

### Шаг 3. Парсинг и санити

- Из каждого движка бери: title, URL, сниппет (обрезка ~200 симв.).
- Релевантность: хотя бы 1 токен запроса (длиннее 4 симв.) в title или сниппете
  топ-3 результатов. Нет → результат движка бракуется.
- Точная фраза (запрос в кавычках): считай движки, давшие **прямое вхождение**
  фразы в сниппете/тайтле. 0 из ≥2 живых → вывод «фраза в вебе не индексирована».

### Шаг 4. Доклад пользователю

```
Живо: Яндекс ✅, Google ✅ | Отравлены: Bing (гео-мусор) | Мертвы: DDG (DNS)
Найдено (Яндекс): 1) … 2) … / Контроль (Google): совпадает | расходится
Вывод: … | Уверенность: высокая/средняя/низкая (почему)
```

Если всё мертво/отравлено: предложить (а) выключить VPN и повторить,
(б) GUI-режим browser-pilot для ручной капчи, (в) дать контекст для прицельного
поиска (site:youtube.com и т.п.), (г) **bypass-режим: известные URL напрямую**
(см. ниже) — не упирайся в движки, если сеть вообще жива.

### Bypass-режим: известные URL напрямую (когда движки умерли, а сеть жива)

Реальный кейс (2026-09-28, VPN-выход): Google отдал капчу в headless, DDG пустой,
Яндекс недоступен — но `webfetch`/curl по **конкретным** сайтам работал нормально.
Поисковики — не единственный вход в веб:

1. Сходи **напрямую в известные первоисточники** по теме: официальные доки
   (developer.mozilla.org, docs.python.org, ru.wikipedia.org), GitHub
   (`github.com/search?q=...` или прямой путь к репо), changelog/release notes.
2. Внутренний поиск сайта: `site.com/search?q=...` у многих ресурсов работает
   без капчи, в отличие от глобальных движков.
3. Навигационные запросы («официальный сайт X») заменяются угадыванием домена
   + проверкой через `webfetch` — это честный результат, фиксируй источник.
4. В докладе явно пиши: «движки мертвы (диагноз), искал прицельно по
   первоисточникам» — это не то же самое, что полноценный поиск.

## Спид-режим (ресёрч по теме за <1 минуты)

Когда нужен не единичный запрос, а подборка материалов по теме:

1. **Пропусти диагностику**, если сеть проверялась в этой сессии недавно.
2. **Тёплый профиль**: капча Google, пройденная хоть раз (GUI), живёт в cookies
   профиля `_default` — дальше всё летает headless. Если капча вылезла — один
   GUI-прогон с ручным кликом, и профиль снова тёплый.
3. **Батч запросов в одной сессии**: один exec-скрипт, 5-7 запросов по аспектам
   темы (official / learn / practice / resources / ru / fresh), между запросами
   только `time.sleep(2.5)` — не закрывай браузер. Замер: 6 запросов ≈ 18 сек.
4. **Резолв редиректов — только для топа.** Google отдаёт ссылки как
   `google.com/goto?url=<токен>` (и `/url?...`) — реальный URL получай
   `page.goto(ссылка, wait_until="commit")` → `page.url`. Резолвь только
   отобранный вручную топ (~15-20 шт), не весь сырой дамп.
5. **Фильтр мусора до показа**: дропай AI-заглушки Google («Ответ в режиме ИИ»),
   дубли по домену, ссылки не на языке раздела. В доклад — только живые URL.

## Прокси-браузер (когда VPN обязателен)

Если контент доступен только с российского IP, а VPN уже включён — обычный
порядок. Если наоборот (нужен «чистый» IP) — см. скилл `firefox-pilot`
(VPN-браузер). Сам web-search просто выбирает живой путь.

## Типовые фейлы и что делать

| Симптом | Диагноз | Лечение |
|---|---|---|
| `HTTP 000` / `ERR_NAME_NOT_RESOLVED` у всех | DNS/транспорт закрыт VPN-выходом | Шаг 1, предупредить юзера |
| Google `/sorry/`, 429 | IP-выход в чёрном списке | browser-pilot GUI (юзер щёлкнет капчу) или скип |
| Google капча headless + DDG пусто (VPN-выход) | оба движка недоступны с этого IP, сеть жива | не упирайся: bypass-режим «известные URL напрямую» + GUI-капча как опция |
| Яндекс `showcaptcha` | то же | то же |
| Bing: результат не на языке запроса | гео-отравление IP | пометить мёртвым, не показывать |
| Все живые движки: 0 точных совпадений по кавычкам | фраза не индексирована | так и сказать: стрим/голос/личка |
| webfetch на поисковик → transport error | тулза не тянет эти хосты | не упирайся, бери curl/browser-pilot |

## Демон: где живёт, что жрёт, что после перезагрузки

- **Что это:** headless-Chromium + python-обёртка (`tools/web_daemon.py`), порт
  `localhost:9222`. Профиль общий с browser_pilot (тёплые cookies).
- **Ресурсы:** ~190-230 МБ RSS, CPU ~0% в простое (событийный — работает только на запрос).
- **Анти-утечка (кейс 2026-09-29: 1.1 ГБ за 5 дней):** healthcheck — HTTP-проба
  `/json/version` без открытия страниц; все вкладки CDP-клиентов закрываются в
  `finally` (`browser_fetch`, search/resolve-воркеры). Правило для новых тулз,
  работающих с демоном: **каждая созданная вкладка закрывается в finally** —
  вкладка ЯМ/onlinetrade с service worker'ами весит 50-150 МБ.
- **Перезагрузка MacBook:** обычный процесс умирает, НО установлен LaunchAgent
  `~/Library/LaunchAgents/com.radmipa.web-research-daemon.plist` — поднимает демона
  при логине (RunAtLoad) и воскрешает при падении (KeepAlive). Обёртка сама
  зачищает зомби-захватчиков порта и умирает вместе со своим chromium (healthcheck
  10 сек) — launchd перезапускает целиком.
- **Установка агента на новой машине** (один раз): скопировать plist из
  `radmipa-skills` в `~/Library/LaunchAgents/` (поправить пути) →
  `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.radmipa.web-research-daemon.plist`.
- **Проверка:** `nc -z localhost 9222` / лог `/tmp/web_research_daemon.log`.
- Если демона нет — тулза работает и без него (холодный запуск, медленнее).

## Глубокий ресёрч (когда цена ошибки высока)

Для критичных утверждений (выбор технологии, безопасность, деньги):
- **Триангуляция:** ≥3 независимых источника на каждое ключевое утверждение.
  «Независимых» = не перепечатывающие друг друга.
- **Дословные цитаты:** выжимка только с точными формулировками источника + URL.
- **Расхождения фиксируются явно:** «источник А говорит X, источник Б — Y».
- **Свежесть:** дата публикации/коммита у каждого источника; prefer официальные
  changelog/release notes над блогами.
- Итог — брифинг: выводы → доказательная база (цитата+URL) → что осталось
  неясным.
