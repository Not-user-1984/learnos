# Ресёрч hermes-agent: паттерны для LearnOS

Дата: 2026-10-17. Источник: `nousresearch/hermes-agent` (MIT), клон изучен целиком.
Фокус: качественный ресерч источников, браузер, инструменты, контекст, агентный цикл.
Краткая выжимка — в [../hermes-ideas.md](../hermes-ideas.md); задачи — [T-014](../tasks/T-014-research-v2.md), [T-015](../tasks/T-015-browser.md).

## 1. Поиск: provider-реестр, а не «один движок»

- Каждый вендор — плагин с единым контрактом (`search()/extract()/is_available()`); выбор — лестница автодетекта по наличию ключей, явный конфиг всегда сильнее (`agent/web_search_registry.py`, `tools/web_tools.py:100-155`).
- **Keyless-ring rescue**: упавший платный бэкенд обслуживается одноразово кольцом бесплатных (round-robin, детект 429/401-403 по маркерам); rescue-результат никогда не кэшируется — fallback не «прилипает» (`tools/web_tools_rescue.py`).
- Кэш: in-memory TTL (20 мин) со **single-flight** (параллельные одинаковые запросы делят один вызов) + дисковый кэш экстрактов, ключ `sha256(url+format+provider)`, лимит записей, бакетинг лимитов (`tools/web_result_cache.py`).
- Итеративного research-цикла в коде нет — он в скиллах: breadth-then-depth, критерий остановки «>80% уже виденных результатов = насыщение, обычно 2–3 раунда» (`optional-skills/research/research-paper-writing/SKILL.md:279-300`).

**→ LearnOS**: модуль `research`: `SearchProvider` ABC + реестр (SearXNG self-hosted / DDGS / Tavily по ключам), keyless-rescue, single-flight кэш. Насыщение — как stopping-критерий агента-ресёрчера.

## 2. Браузер: a11y-tree, а не скриншоты

- Браузер — toolset поверх отдельного CLI (Node/Playwright): `navigate/snapshot/click/type/scroll/vision`; в LLM идёт **accessibility-tree с refs `@eN`** — дёшево и детерминированно, скриншот — отдельная опция (`tools/browser_tool.py`).
- Сессии на задачу, авто-снапшот после navigate, гибридный роутинг приватное→локальный sidecar / публичное→облако, SSRF-проверка до navigate и на каждом редиректе, scrubbing env для подпроцесса.
- Oversize-снапшоты = веб-страницы: truncate по границам строк, полный текст на диск, агенту — путь и инструкция «долистать» (`tools/browser_tool_snapshot.py:69-107`).

**→ LearnOS**: браузер — **третья линия** после search+extract («URL упал / JS-рендер — открой браузером»). Для ресерча чаще всего хватит связки search+extract; интерактив (a11y-refs) — когда понадобится обход логинов/SPA.

## 3. Извлечение страниц: truncate-and-store

- Страница >15K символов → окно 75% head + 25% tail, разрез по строкам, полный текст на диск (потолок 2M), **футер с готовым вызовом дочитать середину** (`tools/web_tools_truncate.py:86-128`).
- Гигиена: inline base64-картинки → `[IMAGE: alt]`; бинарный детект по magic-bytes (SQLite/ZIP/ELF не «текст»); SSRF + блок cloud-metadata + защита от DNS-rebinding; `?token=`-параметры вылавливаются до передачи третьим лицам; пользовательский blocklist доменов (`tools/url_safety.py`).

**→ LearnOS**: фундамент библиотеки: полный текст страницы — документ в библиотеке с постраничным доступом (наш `read_chapter`-паттерн!), в контекст — окно + offset-указатель. Base64-свип и бинарный детект — копировать как есть.

## 4. Grounded citations — жемчужина для системы обучения

(`skills/research/grounded-citations/SKILL.md`)

- Ледджер источников: `sources add <url>` → стабильный id `[1]` (idempotent, URL-нормализованы); цитирование в момент драфта `[1][2]`; блок Sources генерируется механически — модель никогда не перепечатывает URL.
- **Fact-checking**: к источнику цепляется дословная цитата; цитата **отвергается, если её нет буквально** в сохранённом тексте страницы (проверка кодом, без LLM); непроверяемое — `[unverified]`; гейт `verify --min-coverage 0.5`. Спорные факты — два независимых источника.
- Цикл верификации в research-письме: SEARCH → VERIFY (2+ источника) → RETRIEVE (метаданные по DOI, не из памяти) → VALIDATE (клам реально в статье) → ADD; провал → `[CITATION NEEDED]`.

**→ LearnOS**: модуль цитат: таблица «утверждение → источник → дословная цитата», проверка дословности по тексту главы в библиотеке (он у нас уже хранится!). Это и есть «проверка фактов и сравнение источников» для конспектов. Прямо усиливает ядро продукта: конспект с прослеживаемостью до цитаты.

## 5. Инструменты: реестр с гейтами и трёхслойная обрезка

- Регистрация: schema+handler+`check_fn` (дешёвая видимость: нет ключа — тул скрыт) + per-tool `execution_timeout` + `max_result_size_chars`; валидация схемы на регистрации (`tools/registry.py:709-790`).
- Обрезка результатов: per-tool лимит → **spillover на диск** (модели — preview+path в `<persisted-output>`) → per-turn бюджет; ошибки для контекста — максимум 2048 символов (`tools/tool_result_storage.py`).
- Опасные операции: паттерн-детект → smart approval (guardian-LLM c вырезанием shell-инъекций), permanent allowlist, «denial breaker» (3 DENY подряд → стоп).
- Progressive disclosure: длинный хвост тулов за мостами `tool_search/describe/call`.

**→ LearnOS**: у нас уже есть ToolRegistry — добавить `check_fn`-гейты и `max_result_chars` per-tool (сейчас один глобальный); spillover больших результатов «на диск + путь» — обязателен перед длинными research-пробегами. Approval с denial-breaker — для деструктивных операций над библиотекой/базой.

## 6. Контекст: head+tail защищены, история не теряется

- Компакция: aux-модель суммаризирует середину, head/tail не трогаются; иерархия мер (суммаризация → tail-budget → выпрямление tool-выводов → обрезка); commit-fence, durable-lock, cooldown после неудач (`agent/context_compressor.py`).
- Компакция = дочерняя сессия с lineage: старая ветка остаётся в поиске — история не теряется.
- Файловая память (MEMORY.md/USER.md) — frozen-снимок в системный промпт на старте (prefix cache цел), изменения через инструмент.
- Read-coverage: линейные диапазоны «что уже прочитано», дедуп повторных чтений, loop-детектор (`tools/file_tools_read_tracking.py`).

**→ LearnOS**: у нас уже есть summary-компакция истории чата — развить: защищать head/tail, «demote» старых tool-результатов до заглушек; lineage разговоров при компакции; read-coverage — идеален для «что агент уже прочитал из транскрипта/главы».

## 7. Делегирование и цикл

- `delegate_task`: дочерний агент с чистым контекстом и урезанным toolset; **родитель видит только итоговый summary** — радикальная экономия контекста; batch-режим, глубина спавна, steering (`tools/delegate_tool.py`).
- Фоновый self-review после хода (макс 3 попытки); todo-инструмент с гидратацией из истории; `clarify` — переспросить человека вместо угадывания; execute_code-RPC (скрипт в песочнице зовёт инструменты агента — многошаговый pipeline одним ходом).

**→ LearnOS**: делегирование — ядро research-агента: родитель-синтезатор спавнит детей по направлениям (доки/статьи/видео/форумы), каждый возвращает structured summary + ссылки. В нашем рантайме — суб-запуск `run` с урезанным toolset и `parent_run_id` (поле уже есть в трейсах!). Фоновый review — модель для «проверки конспекта после генерации».

## Топ-5 заимствований (ценность/усилия)

1. **Truncate-and-store + постраничный доступ** — низкие усилия; фундамент: веб-страница становится документом библиотеки, контекст под контролем.
2. **Ледджер источников + дословный verify цитат** (grounded-citations) — средние усилия; уникальная ценность для образования: конспект с прослеживаемостью, fact-checking без LLM.
3. **Provider-реестр поиска + keyless-rescue + single-flight кэш** — средние усилия; устойчивый бесплатный ресерч для персональной системы.
4. **Delegate-подагенты (summary-only)** — средневысокие; параллельный сбор источников без раздувания контекста.
5. **check_fn/лимиты/spillover в реестре тулов** — низкие; защитная гигиена до длинных пробегов.

Анти-урок: Hermes нигде не кодирует «качество источников» (кроме скиллов) — рейтинг/сравнение источников придётся строить самим; для LearnOS это может стать отличительной фичей (связь с T-003 «понятия как сущности»: расхождения определений между источниками).
