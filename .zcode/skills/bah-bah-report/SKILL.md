# Бах-бах-Репорт: записал — и пошёл тестировать дальше

Пользователь ходит по продукту (книги, сессии, база знаний, чат) и на ходу диктует недостатки.
Задача скилла — превратить живое наблюдение в короткую самодостаточную запись с пониманием кода,
чтобы позже исправить всё пачкой. Единый файл записей: `task_ai/bah-bah-report.md`.

## 1. Когда что делать

- «запиши баг-репорт …» / «запиши идею фичи …» / «бах-бах …» → режим записи (§2)
- «покажи бах-бах» / «что накопилось» → сводка (§4)
- «запусти бах-бах» / «пора чинить по бах-баху» → фаза исправления (§5)
- Просьба «запиши и сразу почини» → сначала запиши (§2), затем скажи: «в очереди на пачку;
  запустить исправление сейчас?» — и действуй по §5 только после явного согласия.

## 2. Режим записи (баг или фича)

1. **Интерпретируй** сказанное. Запись — не стенограмма: сформулируй суть своими словами,
   одним предложением. Если совсем непонятно, о чём речь, — задай ОДИН короткий вопрос;
   в остальных случаях трактуй сам (трактовка фиксируется в поле «Симптом»/«Идея»).
2. **Разберись в коде** — read-only и быстро. Найди модуль и файлы, за это отвечающие,
   пойми, как устроено сейчас. Достаточно 2–5 предложений и 2–4 ссылок `путь:строка`.
   Это контекст для будущего фикса, а не расследование до конца: гипотезу причины
   сформулируй, если она дёшево видна, иначе честно напиши «не разбирался глубоко».
3. **Проверь на пересечения** — обязательно перед записью:
   - прочитай весь `task_ai/bah-bah-report.md`. Тот же корень проблемы, что у существующей
     записи → НЕ создавай дубль, дополни существующую строкой «Дополнение» (§3). Смежное
     или противоречащее → проставь взаимные ссылки в поле «Связано» у обеих записей;
   - глянь реестр `task_ai/bugs/` и открытые `task_ai/tasks/`: если проблема уже известна,
     запись всё равно создай (это inbox пользователя), но в «Связано» укажи `BUG-…`/`T-…`.
4. **Запиши.** Возьми следующий свободный `BB-<ннн>` (нумерация сквозная на баги и фичи
   вместе). Добавь запись по шаблону §3 в конец секции `## Баги` или `## Фичи` и строку
   в таблицу-оглавление в шапке файла. Больше ничего в файле не меняй.
5. **Ответь коротко:** «Записал BB-004 „заголовок": <одной строкой — как устроено или
   гипотеза>. Похоже на BB-002 — связал». Ничего не чини и не предлагай чинить (кроме
   случая из §1).

## 3. Шаблоны записей

Баг:

```md
### BB-<ннн> · bug · open · <дата> · <заголовок>

- **Симптом:** что происходит (уточнённая формулировка пользователя)
- **Ожидание:** как должно быть
- **Как устроено:** <2–5 предложений о текущем коде> (`server/app/...py:123`, `web/src/...tsx:45`)
- **Гипотеза:** вероятная причина или «не разбирался глубоко»
- **Воспроизведение:** шаги, если известны; иначе «—»
- **Контекст:** канал и стенд (веб/прод CT 132 / локально)
- **Связано:** BB-…/BUG-…/T-… или «—»
```

Фича:

```md
### BB-<ннн> · feature · open · <дата> · <заголовок>

- **Идея:** чего хочет пользователь (уточнённая формулировка)
- **Зачем:** какую боль закрывает
- **Куда приляжет:** код, который это заденет (`путь:строка`), и смежные записи
- **Связано:** BB-…/BUG-…/T-… или «—»
```

Дополнение к существующей записи — строка внутри неё:

```md
- **Дополнение <дата>:** <наблюдение или уточнение>
```

## 4. Сводка

Прочитай файл и выдай: счётчики (баги/фичи × open/tasked/fixed) и списком все open-записи
`BB-<ннн> · заголовок`. Без анализа и планов, если не просят.

## 5. Фаза исправления («запусти бах-бах»)

Запускается ТОЛЬКО по явной команде пользователя, не по своей инициативе.

1. Прочитай все `open`-записи и сгруппируй по областям кода (модуль server / экран web /
   infra) так, чтобы группы не пересекались по файлам. Записи, которые цепляют одни файлы,
   — в одну группу. Правки общей доки (AGENTS.md, README) — отдельным шагом одной группы,
   остальные группы в это время доку не трогают.
2. Группы исполняй **последовательно**, по одной: для каждой запусти субагента `learnos-dev`
   с самодостаточной постановкой — перепиши записи группы в задачу (симптом, ожидание,
   код-рефы, контекст, «Связано») и потребуй его полный воркфлоу
   (код → тесты → пуш → деплой → самопроверка прода → задача в task_ai → обновление доки).
   До старта пометь записи группы `tasked`, чтобы не взять повторно.
3. По мере закрытия группы помечай её записи `fixed` со ссылкой на задачу/коммит
   (строка `- **Исправлено:** T-… / <коммит>`), статус в оглавлении тоже обнови.

## 6. Жёсткие правила

- В момент записи не исправлять ничего: ни код, ни данные, ни task_ai — правится только
  единственный файл `task_ai/bah-bah-report.md`.
- Все записи живут только в этом файле; не заводить отдельных файлов под записи.
- Статусы записей меняются только в фазе исправления (§5) или по явной просьбе пользователя.
- Файл — inbox, он не заменяет реестр `task_ai/bugs/` и задачи `task_ai/tasks/`:
  конвертация туда происходит в фазе исправления.
