# ub-mode: сначала работает → потом правильно → потом практика

Полный перевод с оригиналом: `task_ai/reference/ub-mode-ru.md`. Правило кодинга
репо: `task_ai/07-code-standards.md`, раздел «Принципы ub-mode». Ниже — рабочая
выжимка: что проверять перед каждым изменением.

## Фаза 1 — сначала заставь работать

- **Протокол лени**: одно решение в одном месте; минимальная правка, решающая
  проблему. Не добавляй функций «на вырост».
- **Форма данных раньше логики**; сначала делай то, что поможет следующим фазам.
- **TDD**: падающий тест до правки; падает по ожидаемой причине; минимальный
  фикс. Честный тест нецелесообразен — не пиши плохой.
- **Не прикручивай к старому дизайну**: спроси, что построил бы с нуля, доставляй
  кусками.
- **Два фикса на одной предпосылке валятся об один шлюз** → запиши предпосылку
  предложением, убери перекос, только потом новые фиксы.
- **Сначала вычти, потом добавляй**: сложность убирается до добавления.
- **Построй рычаг**: непонятную с одного взгляда работу делаешь инструментом
  (одну единицу руками → инструмент повторяет).
- **Архитектура**: невозможные состояния невыразимы; проверка на входе, доверие
  внутри; чистые функции для логики; не заглушать компилятор; идемпотентность;
  у изменяемого состояния один писатель.

## Фаза 2 — потом сделай правильным

- **Корневая причина**: воспроизведи → почини причину; страж, прячущий падение,
  не считается.
- **Малые проверяемые единицы**: закончил → проверил → следующая.
- **Тест поведения, не реализации**: тест зовёт код как пользователь; тест,
  зелёный при пустых функциях, — выбросить.
- **Гейты**: `ruff` + `mypy` + `lint-imports` + `pytest` зелёные; дубли и
  громоздкие функции режутся сразу; мёртвый код удаляется.

## Фаза 3 — следуй практике

- **Журнал**: каждое действие + причина; отчитайся журналом в конце.
- **Контекст главного — маленький**: масса в субагенты/файлы, себе — саммари.
- **Коммиты**: часто, малые, упорядоченные; «почему, что, чем доказано».
