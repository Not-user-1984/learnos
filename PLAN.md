---

## 1. Суть

Персональный «конструктор курсов» + база знаний, которая растёт **только через понимание**.

Пайплайн:

1. **Ресерч** — с ИИ ищем источники по теме (книги, курсы, видео, бесплатно)
2. **Отбор** — сам смотрю список, выбираю, что качаем
3. **Загрузка + план курса** — источники обрабатываются, строится план
4. **Сессии по 30–40 минут:**
   - Теория блоками (3–5 блоков) — ИИ объясняет
   - Обратное объяснение (фейнман-метод) — ИИ спрашивает, я отвечаю своими словами, ИИ корректирует и говорит, что понял/не понял
   - Практика ~50% времени — руки: терминал, виртуалка на хомлабе, локально на маке
   - Разбор практики → сессия закрыта
5. **Блок в базе знаний** — появляется ТОЛЬКО после проговора: короткие тезисы + мои собственные примеры («как я это понял») + схемы/графики

Ключевой принцип: **блок знаний рождается только через сессию**. Не гора скачанных файлов, а проковиченное.

---

## 2. Требования к базе знаний (почему не Obsidian)

Не нравится внешний вид Obsidian. Хотим:

- красивые карточки-блоки, которые раскрываются (тезисы → примеры → схема)
- граф связей между блоками (интерактивный)
- mermaid-диаграммы прямо в блоке
- работает с мобилки, независимо от мака
- блок виден как «закрытый/пройденный» — с датой сессии, источником

Решение: **свой веб-UI** (см. ARCHITECTURE.md §5). Блоки физически — markdown с frontmatter (портабельно, git-бэкап), UI рендерит.

---

## 3. Архитектура — коротко

Один сервис `learnos`, детали в [ARCHITECTURE.md](ARCHITECTURE.md):

- **Backend:** Python FastAPI + SQLite + файлы на диске (книги, чанки, блоки)
- **Свой MCP-сервер** (streamable HTTP) — сессиями и ингестом управляет любой агент: opencode на маке, OpenClaw на хомлабе
- **Свой веб-UI:** база знаний (карточки + граф), прогресс курсов, веб-чат для сессий с мобилки
- **Ингест:** PDF-сплиттер (сначала оглавление → потом главы, контекст не захламляем), YouTube (портируем готовый скилл `youtube-to-summary`), web-ресерч (портируем `web-search`)
- **Практика:** одноразовые LXC-песочницы на Proxmox (по шаблону, клон на курс) + code-server в браузере → практика доступна даже с телефона

## 6. Зафиксированные решения (2026-10-06)

1. **UI базы знаний:** свой веб-UI (Next.js + React Flow + mermaid) — фаза 2. ✅
2. **Мобильный канал сессий:** веб-чат самого сервиса (сервис сам зовёт LLM). ✅
3. **Сон хомлаба:** пока не блокер — фаза 1 на маке; к деплою (фаза 2) решим: разбудить руками (`wake.py` с мака) + при необходимости сдвинуть таймер сна. ⏳
4. **LLM-провайдер:** z.ai (GLM, OpenAI-совместимый API) как основной; fallback не закладываем в v1. ✅
5. **Git-бэкап:** только `kb/*.md` + метаданные; книги/транскрипты остаются на диске сервера. ✅
6. **Скиллы живут внутри learnos:** скилл = папка `server/skills/<name>/` (SKILL.md + entrypoint), сервис сам регистрирует его как MCP-инструмент; закинул папку — работает из всех каналов (opencode MCP / веб-чат / встроенный агент). ✅
7. **Фронт — с фазы 0/1, а не фазы 2:** Next.js + TypeScript strict; типы API генерятся из OpenAPI (меньше ошибок при кодогенерации LLM); MD-рендер + mermaid сразу, граф (React Flow) — фаза 2. «Obsidian под нас»: kb/*.md — источник истины, UI — наш рендерер. ✅
8. **Harness — клиент, не фундамент:** learnos самодостаточен (FastAPI + MCP + файлы); opencode — первый водитель сессий, внешние обвязки (в т.ч. облачные) подключаются через MCP. ✅
